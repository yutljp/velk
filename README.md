# velk

LLM(エージェント)向けのバイナリ解析エンジン。
バイナリから、会話で解析が完結する形の出力(C 風疑似コード、関数カード、メタデータ)を作る。

## 使い方

```bash
cargo build --release

# 関数一覧
./target/release/velk inspect /path/to/binary
./target/release/velk inspect /path/to/binary --json --limit 200

# 関数カード(JSON)
./target/release/velk fncard /path/to/binary --name <symbol>
./target/release/velk fncard /path/to/binary --addr 0x7c8f0 --preview 32

# 節一覧
./target/release/velk sections /path/to/binary

# 疑似 C(AArch64)
./target/release/velk decompile /path/to/binary --name <symbol>

# シグネチャ DB の生成(名前付き関数から)
./target/release/velk siggen libsyms.o --output sigs.json

# MCP サーバ(stdio; velk_run_script / velk_read_api)
./target/release/velk mcp

# スクリプト API(src/api/*.d.ts)で解析する
./target/release/velk run analyze.js

# 関数ドシエ(型・参照・エビデンス ID を含む JSON)
./target/release/velk report libfoo.so --name target_fn

# 同定結果を decompile / fncard に付与
./target/release/velk decompile stripped.bin --name fn --sigs sigs.json
./target/release/velk fncard stripped.bin --name fn --sigs sigs.json

# シグネチャ DB による関数同定
./target/release/velk identify stripped.bin --sigs sigs.json

# IR のダンプ(AArch64 / x86-64)
./target/release/velk lift /path/to/binary --name <symbol>
./target/release/velk lift /path/to/binary --addr 0x50
```

## 対応範囲

- 形式: ELF(x86-64 / AArch64)、PE(x86-64)、Mach-O(x86-64 / AArch64)
- 関数探索: シンボル表・動的シンボル・PE エクスポート・エントリポイント・
  Go `pclntab`・DWARF subprogram
- 名前: Rust(v0/legacy)と C++(Itanium)のデマングリング
- 関数カード: `fid` / `name` / `source` / `size` / `size_estimated` /
  `section` / `hard_reasons` / `blocks` / `unsupported` / `disasm_preview` /
  `approx_tokens` / `strings` / `name_hints` / `accesses` / `identified`
- デコード: x86-64 / AArch64(戻り・トラップでプレビューを打ち切り)
- リフト: 関数単位のレジスタ式 IR(`velk lift`)。拡張シフト
  (`uxtw`/`sxtw` など)を含むアドレッシング、算術・論理・シフト・load/store・
  分岐・呼び出し・ret を意味化する。未対応命令は `unsupported` として明示。
  32bit レジスタへの書き込みは 64bit 変数への zero-extend として表現する。
  AArch64 は `adrp`/`adr`・間接分岐、x86-64 は 8/16bit 部分レジスタ・
  符号拡張(`movsx`/`movsxd`)・条件選択(`cmov`/`setcc`)・`neg`/`not`/
  `inc`/`dec`・`cdq`/`cqo`+`idiv`・`leave` に対応する
- シグネチャ・型: 引数レジスタ(ABI 別)の読み取りから引数個数を推定し、
  ポインタ利用から `uint32_t *` などを推定する。DWARF があれば引数名・型・
  戻り値型で上書きする。ブロック間の前後関係は分岐に加えて
  **フォールスルー**も辺として数える (抜けていると初期化ブロックの後の
  引数が「既に書かれた」と誤認され、引数リストが空になっていた)
- 構造体アクセス: ポインタ引数のオフセットと幅を復元し、疑似 C と関数カードに
  注記する(例: `p +0x0:uint32_t, +0x4:uint32_t`)
- データ参照: IR の定数から文字列・データ参照を復元する(ポインタ経由の
  文字列も解決)。文字列から関数名候補(`name_hints`)を生成する
- シグネチャ DB: 名前付き関数の IR 形状を DB 化し(`siggen`)、別バイナリの
  関数を形状ハッシュで同定する(`identify`、`--sigs` で `decompile` /
  `fncard` / `report` に適用)
- 定数除算の復元: `(x * 0xaaaaaaab) >> 0x21` のような乗算とシフトの定数
  除算を `/ 3` などの C 風表記に戻す。符号ありは上位部と符号フラグの和の
  形とレジスタコピーも回復する。64bit は `umulh`/`mul`/`smulh`/`imul` の
  高部分の Produc を見分けて同じ復元を適用し、32bit 値の64bit 拡張を経由
  する符号割も domain を下げて復元する。さらに `select(x >= 0, x, x +
  (2^k - 1)) >> k` の符号 select 形も `/ 2^k` に戻す。ARM64 の
  `smull` 積に `asr` 後のマスク狭窄と `lsr 31` 符号フラグが続く
  スケール形 (`int x / 10`) も `/ 10` に復元する。AArch64 の `csel` は
  直前のフラグの比較を署名述語とする select に持ち上がり、
  `add/csel/asr` 形の符号付き2べき除算も `/ 16` に復元する。補語の
  乗算アンワインド (`q += q << k` の積に戻して `x` から引く形式) と
  `msub` の (x - q*d) 形は `% d` に復元し、符号/符号なし双方で
  `BinOp::DivU` / `ModU` の真の無符号命令を生成する。`csinc/csinv/csneg`
  族は fold 付き select に持ち上げ、`and`+`csneg` の 2 の冪剰余
  (`x % 16`, `x % 4`) は select から `% d` に畳む。除算/剰余の復元は
  被除数の実際の幅 (`asr` の対象レジスタ幅と零拡張マスク) から型を
  決めるので、`int` の `/16`, `%10` が `int32_t` として出る
- 一時変数化: 同一文内で繰り返される同じ計算を `t1`/`t2` の一時変数に
  束ねる(デコンパイラの共有部分式整理と同じく可読性を上げる)
- 否定は `0 - x` ではなく `-x` と出力する(成熟したデコンパイラの
  補数イディオム表記に合わせる)。128bit 乗算の上位半分は中置記号ではなく
  組み込み関数の形 (`__umulh(a, b)` / `__smulh(a, b)`) で出力する
- 演算子の優先順位: 子式は必要なときだけ括弧で括る。`x8 = (w8 * w9);`
  ではなく `x8 = w8 * w9;`、`((a0 < 0x0) ? (a0) : ((-a0)))` ではなく
  `(a0 < 0x0 ? a0 : -a0)` と出力する。マスク (`& 0xffffffff`) は適用
  範囲が読めるよう外側を括弧で括り、畳んだマスクは子の強さを引き継ぐ
- 代数整理: 二重否定 (`0 - (0 - x)`) と `x ± 0` を畳み、絶対値の
  `(x < 0) ? x : -x` 形がそのまま読める。符号拡張の内側にある
  `& 0xff` / `& 0xffff` は拡張幅と同じマスクなので落とす
- 2 の冪の剰余: 符号付き `x % 2^k` の丸め選択 (`csel/csneg` と
  `and`+`cmov` の両形) を `% d` に畳む。`cset/csetm` は
  `select(cond ? 1 : 0)` として持ち上がり、比較は `csel` と同じ
  直前フラグの述語を読む
- 複合代入: `t = *p; t = op(t, x); *p = t` と、ロードがすでに更新式へ
  畳まれた `t = op(*p, x); *p = t` の両方を `*p = op(*p, x)` に融合し、
  名前のある対象 (ローカル・メンバ・グローバル) では `p += x` と表示する。
  一時変数が他の文から読まれない場合だけ融合する
- マスク越しの畳み込み: 32bit 値の一時変数を `reg & 0xffffffff` の読みへ
  畳み込む。他のブロックが読む一時変数でも、そのブロック内で後から
  再定義されるなら畳む (外側の読み手は後の値しか見ない)
- 一時変数の畳み込み: 使用が1回だけの一時レジスタ (コピー、32bit 値の
  拡張、小さな純粋式) を消費者へ畳み込む。幅の食い違いは式の実幅で
  判定するので、32bit 計算を64bit 読み出しへ持ち込むことはない。
  畳み込み→死コード除去→整理→畳み込みの2巡で連鎖を解き (先に死んだ
  読み手を落として単一使用を成立させる)、2巡目は CSE が作った一時
  変数を再び展開しない。読み手がその後で再定義される場合は畳める
  (生存判定は次の定義まで)。
  x86 の関数フレーム (`push rbp`/`leave` 相当) はフレームポインタが
  読まれないときに前後ごと落とす
- 死んだフレームストア: フレーム相対のストアのうち、同じスロットを読む
  ロードが関数内に一つも無いものを落とす (`-O0` の引数退避
  `local_0 = a0;` や、戻り値に使われない計算結果)。フレームアドレスが
  呼び出し先へ渡っている可能性がある形では何もしない。フレーム確定後に
  実行するので、スロットの対応が一意になる
- 畳み込みの幅: 置換する値の幅は `expr_width` で決め、32bit の値
  (零拡張されたロードや 32bit 演算)は 64bit レジスタの読み出しにも入る。
  これで `a0 = a0 / 0x3; return a0;` が `return a0 / 0x3;` になる。
  値が読み手の書き込み先自身を読む場合は畳まない (自己参照の式を作らない)
- シグネチャ DB のトークン: 戻り値・ストアの値とアドレス・switch の
  インデックス・間接分岐の対象も含める。従来は `ret` のみだったため、
  「値を返すだけ」の関数がすべて同じハッシュに衝突していた
- ブロック内コピー畳み込み: 定義が「同じブロック内で、レジスタが書き換わる
  前の 1 回だけ」読まれる場合、その値を読み手に埋め込んで定義を消す
  (`x8 = w8; if (x8 & 0x80000000)` → `if (w8 & 0x80000000)`)。値が読む
  レジスタが途中で書き換わる場合と、**ループ本体(自分自身へ到達できる
  ブロック)** は対象外 — 周回で更新が失われるのを防ぐ
- ストア→ロード転送: 同じ幅・同じアドレスへのストアの直後にそのスロットを
  読み戻す場合、読み出しをストアした値で置き換える (`local_3 = w8;
  x8 = local_3;` → `x8 = w8;`)。スタックポインタの増減・関数呼び出し・
  同じスロットへの別のストアで転送は無効になる
- 死んだ代入の掃除: 読み出しの無い代入を不動点まで除去する。フレーム
  内の読み出し (ローカル) は副作用が無いので落とし、フレーム外の
  読み出しは volatile の可能性があるので残す。加えて制御フローを
  またいだ生存解析 (live-in/live-out の不動点) で、どの経路からも
  読まれない定義 (ループ直前の死んだ代入など) を落とす。呼び出しは
  呼び出し先が書くレジスタを全て生かし、未対応命令・間接分岐を含む
  ブロックは「すべてを読む」として扱い、そのブロックの定義だけ残す
  (未対応命令を含む関数でも他のブロックの死んだ定義は落とせる)。
  レジスタの読みは式の入れ子も再帰的に集計し、他のブロックからの
  読み出しは定義を生かしたままにする
- スピルの除去: 呼び出し先保存レジスタの退避/復元 (同じスタック
  スロットへの store と load、間で当該レジスタを読まない) を前後
  まとめて落とす。フレームポインタ設定と、退避専用だったフレーム
  調整も一緒に消える。スタック変位はレイアウト順に追跡するので
  別ブロックにあるプロローグとエピローグでも同じスロットと分かる
- 変位の正規化: `(sp + k1) + k2` を `sp + (k1+k2)` に畳み、負の
  変位は `sp - 0x20` と引き算で表示する
- ポインタのメンバ: ポインタ型パラメータの `p + k` アクセスは、同じ
  幅で読むフィールド表にあるとき `p->field_0x4` として表示する
  (幅が食い違う場合はキャスト表記を残す)。DWARF に構造体のメンバ名が
  あれば `struct pair *p` の `p->a` / `p->b` として表示する
- 再配置の解決: オブジェクトファイルに残った分岐再配置を読み、`bl`/`b`
  の飛び先を実シンボルへ解決する。別関数への `b` はテールコールとして
  呼び出し 1 行で表示し、呼び出し先はシンボル名で書く
  (`ns::mul` → `ns__mul_int__int_()`)
- グローバルの命名: 実行不可セクション内の定数アドレスへのアクセスは
  幅とアドレスから `qword_140003000` のように命名する。既知の
  関数アドレスを値として持つ定数はその関数名で表示する (0 はアドレス
  0x0 のコードと紛れるため定数のまま)
- 表引きの索引: `*(T *)(base + i * sizeof(T))` (`<< k` 形を含む) は
  テーブルへの添字 `dword_200120[i]` として表示する
- スタックローカル: フレーム相対のアクセスをスロット単位で `local_0`
  のように命名し、アクセス幅から `uint32_t local_1; /* [sp-c] */` の
  ように宣言する。フレーム変位は制御フロー上で解くので、`sp` が
  動いた後や複数経路から届くブロックでも同じスロットは同じ名前になる。
  経路によって変位が食い違う場合は命名を諦めて生の表記を残す
- 書き込み先の名前: 読み手が 32bit しか見ないレジスタへの代入は、その
  32bit 名 (`w8 = 0x0;`) で出力する。読み出しの名前と揃う
- マスクの省略: ローカルの宣言幅と同じマスク (`uint32_t` への
  `& 0xffffffff`) は書かない。レジスタの `& 0xffffffff` は 32bit
  レジスタ名 (`w8`/`eax`) として表示する。値が 32bit に収まると
  分かる式 (定数、32bit レジスタ、`&`/`|`/`^`、商・剰余・右シフト、
  それらの `select`) へのマスクも落とす。32bit 型のオペランド同士の
  加減算・乗算は C 側で 32bit に巻き戻るので、その外側のマスクも不要。
  32bit 宣言のパラメータはレジスタ読みが 64bit でも 32bit 値として扱う
  (DWARF の `int`/`unsigned`/`short`/`char`/`uintN_t` も 32bit 以下と判定)。
  符号拡張した値は拡張幅 (符号込み) に収まるので、その外側の 32bit マスク
  も落とす (`(int8_t)(x) & 0xffffffff` → `(int8_t)(x)`)。
  書き込み先のレジスタが 32bit でしか読まれない (読みがマスク越しなら
  32bit と見なす) 場合や、戻り値型が 32bit で書き込み先が戻り値
  レジスタの場合は、ゼロ拡張のマスクも省略する。定数マスクは値の
  上限を決めるので `x & 0xffffffff` はそれ自体が 32bit に収まる値と
  みなす。一時変数 (`t1`) は値の実際の幅を持ち、32bit 幅の左シフトも
  32bit 値として扱う
- 使われ方による型付け: レジスタが 32bit 幅でしか書かれない (または
  読まれない) なら、そのパラメータ/戻り値は 32bit 型にする。戻り値は
  最終的な本体で判定し、64bit レジスタを狭める根拠が無ければ 64bit に
  戻す。32bit 比較 (`cmp w0, #0`) は 32bit 幅で持ち上げる
- ストリップされた像の関数発見: シンボルも DWARF も Go pclntab も無い
  像では、`ret`(または `brk`)と整列詰め物の直後を関数の開始とみなし、
  `fn` として登録する。テールコールで終わる関数も境界になる: セクション外へ
  出る分岐、自分自身を指す分岐(リンカ未解決)、詰め物に着地する分岐、
  レジスタ経由の間接分岐(`br x2` / `jmp *%rax`)はいずれも関数の終わりと
  みなす。未解決のテールコールは無限ループではなく
  引数なしの呼び出し(`sub_<dynamic>();`)として表示する。`-O0` のように詰め物が無い場合は `ret` の直後を
  開始とする。命令を復号して**分岐先になっているアドレスは除外する**ので、
  関数の途中にある `ret`(早期リターン)を新しい関数と誤認しない。実行
  セクションの先頭が詰め物でなければそこも関数の開始とする。これで
  リンク前の `.o` を strip したもの(シンボルもエントリも無い)でも
  4 関数すべてを見つけられる。x86-64 も同じ規則を命令デコーダで適用する。既知の関数の内側(シンボルが範囲を明示して
  いる場合)は追加せず、推定した範囲は次の開始で切り詰める
- 戻り値型は**値の幅**で決める: 64bit レジスタでも、32bit のロードや
  32bit の演算しか含まない戻り値は 32bit 型になる (アドレス計算に使う
  `sp` は幅の判断に数えない)
- 戻り値に現れるフレーム読み出しも `local_N` として表示する (負のスロット
  のみ。正のスロットは呼び出し元が積んだ引数なのでアドレスのまま)
- フレームの確定: `sp` がフレーム相対アドレスの基点としてしか使われて
  いない場合、全アクセスを進入時のフレーム基準へ書き換え、`sp` の
  増減そのものを表示しない (スタック引数や保存した `sp` がある場合は
  従来どおり残す)。フレームから読み出したポインタを経由するアクセス
  (`*(uint32_t *)(local_0 + i * 4)` など) は、そのポインタ読み自体が
  フレーム相対なら確定を妨げない
- 終端のないループ: 自分自身へ戻る分岐は `for (;;) { }` として表示する
- 無条件バックエッジのループ: `while`/`do { } while` のどちらでもない形
  (本体の末尾が無条件分岐で先頭へ戻る) もループとして構造化する。この
  場合は分岐の書き換えを行わず、本体のラベルをそのまま残すので、内部の
  `goto` は元の位置に着地する
- 下端判定ループ: ヘッダが本体の先頭にあり、後方のブロックが条件付きで
  ヘッダへ戻る形を `do { ... } while (cond)` として構造化する (領域への
  外部からの飛び込みが無い場合のみ)。ループの出口への分岐は `break;`、
  ヘッダへの分岐は `continue;` として表示する
- `bic` (`a & ~b`) を持ち上げ、`~` は `x ^ 0xffffffffffffffff` ではなく
  `~x` と表示する
- ループ条件の畳み込み: ヘッダが「値を移すだけ」の一時変数 (`reg` /
  メモリ読み / その幅マスク) ならループ条件へ畳み、`while (true) {
  x8 = local_0; if (x8 == 0) break; ... }` を `while (local_0 != 0)`
  として表示する。算術を含むヘッダは break 形式のまま残す
- 到達しない詰め物: `int3`/`ud2`/`hlt` は復帰しない命令として持ち上げ、
  `__builtin_trap();` と表示してそのブロックを終わらせる。整列用の
  `int3` 連続は 1 行に畳まれ、後続のブロックは到達不能として落ちる
- 使われないローカル宣言: 本文が名前を出さないスロットは宣言しない
- 未対応命令のまとめ: 連続する未対応命令は 1 つのコメントにまとめる
  (`/* unsupported (2 steps): MOVI at 0x88, MOVI at 0x8c */`)。SIMD の
  ベクタペアは読み書きを区別して明示する
- ブロックを飛び越える if/else: 条件分岐が片方の腕へ跳び、素通り側の腕が
  同じ合流点へ跳ぶ形を `if (cond) { ... } else { ... }` に畳む。分岐を
  含むブロックの先行文は必ず if の前に出す (以前は if/else を組む際に
  落ちていた)
- switch の本体: ジャンプテーブルの各 case を `case N:` の下に展開し、
  同じ飛び先を共有する case は同じ本体にまとめる。本体の開始位置が
  飛び先の昇順になる場合のみ構造化し、範囲外へ抜ける case は
  `case N: goto L_x;` として残す
- x86 の `idiv`: 商と剰余は命令前の被除数から作るので、剰余の文を先に
  記録する (商を先に書くと剰余の被除数が商になってしまう)
- 幅の特殊化: 32bit としてのみ読み書きされるレジスタは `w8`/`eax` のような
  32bit 変数として出力し、零拡張マスクを消す(型付き値の方式)。混在
  レジスタは従来どおり `(x & 0xffffffff)` で表す
- 疑似 C: レジスタ変数による C 風コード。if/else・do-while・while(ヘッダ条件)・
  早期 return・ガード節・switch を構造化し、それ以外はラベルと goto で出力する
- MCP: `velk mcp` が stdio で `velk_run_script`(JavaScript を内蔵 QuickJS で実行)と
  `velk_read_api`(API の目次と `.d.ts`)を公開する。開いたバイナリと関数ごとの
  解析結果はセッション中キャッシュされる。同じ API を `velk run <script.js>` でも使える
- 性能(release、本機 20 回平均): 46MB 級 ELF の関数走査 6ms 前後、
  1 関数の lift/decompile 2〜3ms、20MB 入力の inspect 6ms 前後

## 既知の制限

- SIMD・浮動小数点・一部のシステム命令は未対応(`unsupported` 表示)
- x86-64 の文字列命令や `shld` など一部命令は未対応
- ジャンプテーブル switch の復元は AArch64 の clang 形式に対応。
  x86-64 の間接 switch は goto のまま残る
- 構造体はオフセットと幅のみで、フィールド名は推定しない
- シンボルも DWARF も無い stripped Rust バイナリは関数名を復元できない
- DWARF 引数は宣言順と ABI レジスタ順が一致する場合のみ正しく対応する。
  再配置が未適用のオブジェクトでは文字列表の基準がずれるため、名前が
  識別子として読めないときは推測した名前・型を残す (パラメータ数が
  食い違うときも推測した個数を維持し、一致する範囲だけ上書きする)
- 増分キャッシュ・並列解析は未実装(実行ごと・関数単位で解析する)

### 正本(1番台)はコンテナ、手元は環境差分

x86-64 の Linux コンテナで固定版のツールチェーンを回し、その結果を正本に
する。手元(macOS/arm64 など)の結果は環境差分として比べる。

```bash
docker compose run --rm canonical      # 高速な正本検証: smoke + ladder + toolchain
# dump が必要なときだけ明示的に有効化（長時間かかる）
docker compose run --rm -e VELK_DUMP=1 canonical
./tests/make_fixtures.sh && ./tests/smoke.sh && ./tests/ladder.sh
./tests/dump.sh tests/out              # 手元の疑似 C を関数ごとに書き出す
./tests/env-diff.sh --show 3           # 正本との差分(一致/不一致/片側のみ)
```

実行時間(このマシン、Apple M3 + Rosetta):

| 場面 | 時間 |
|---|---|
| 初回(イメージビルド込み) | 約 4 分 |
| 2 回目以降(ビルドキャッシュ + フィクスチャ再利用、dump なし) | 約 33 秒 |

速さのための仕掛け:

- `target/` と cargo のレジストリを**名前付きボリューム**に置き、実行ごとに
  フルビルドしない(`cargo-target`, `cargo-registry`)
- フィクスチャは**ツールチェーンの指紋とソースの新旧**で再生成を判定する
  (変わりがなければ 0.1 秒)。強制するときは `VELK_FORCE_FIXTURES=1`
- 疑似 C のダンプは関数ごとに decompile するので重い。既定は無効で、必要な
  ときだけ `-e VELK_DUMP=1` で生成する
- 実行時間の計測はエミュレーションでは意味がないので `VELK_BENCH=0`
  (性能は手元で測る)

固定している版(compose.yml の `build.args` で上書きできる):

| ツール | 版 | 備考 |
|---|---|---|
| OS | Ubuntu 24.04 | `platform: linux/amd64` |
| clang / lld / LLVM | 18 | `llvm-strip` `llvm-objcopy` も同系列 |
| Rust | 1.98.1 | rustup で固定 |
| Go | 1.23.4 | 公式 tarball で固定 |

`env-diff.sh` の読み方:

- **一致** — 環境が変わっても同じ疑似 C(移植性が高い)
- **不一致** — コンパイラ/版による codegen の差(実装の穴か、形の違い)
- **正本のみ / 手元のみ** — 片方でしか復元できていない関数(実装の穴)

`ladder.sh` は `tests/expect/ladder.tsv` を1行ずつ評価し、段ごとの通過数を出す
(L0 算術 → L1 分岐 → L2 ループ → L3 定数除算 → L4 メモリ → L5 分岐表 →
L6 ABI/異常系 → L7 Go・Rust)。1行は `has`（含む）/ `nothas`（含まない）/
`count`（関数数）/ `has_any`（`A|B` のどれか）で書き、コンパイラによって
形が変わる箇所は `has_any` にする。未到達の項目は `known_*` として TODO に分け、
通過した項目は「昇格候補」として知らせる。現時点のラダーでは全項目を必須期待値に昇格済み。

ホストの `clang` / `lld-link` / `clang++` / `rustc` / `go` で回帰用サンプル
(PE64、AArch64 ELF、Mach-O、Go、Rust、C++、DWARF、20MB 入力)を
`tests/cases/` から生成し、`inspect` / `fncard` / `lift` / `decompile` /
`siggen` / `identify` / `report` / MCP の契約を検査する。生成物は
`tests/out/` に置かれ、リポジトリには含まれない。

`bench.sh` は 1 コマンドあたりの平均実行時間を測り、しきい値を超えると
失敗する(例: 小規模入力 120ms、20MB 入力 300ms)。`ITER` で反復回数を
指定できる。

`go` が見つかる場合(`PATH`、`GO_BIN`、`/usr/local/go/bin/go` の順に探す)、
stripped Go バイナリも生成し、`pclntab` からの関数名復元を検証する。
見つからないツールチェーンのケースは `tests/out/skipped.txt` に記録され、
ラダーでは SKIP として扱われる(FAIL にはしない)。
