# 式の等価性テスト

通常の Rust 単体テストには、テスト専用の Z3 検証が含まれます。
`cargo test --release --lib smt -- --test-threads 3 --nocapture` で実行できます。
整数の条件式と支配する条件の検証は
`cargo test --release --lib passes::deobfuscation -- --test-threads 3` でも実行できます。
PATH に Z3 が必要です。存在しない場合は明確なスキップ理由を表示します。
C 出力の検証には Clang と uv も必要です。Python は
`uv run --no-project tests/smt_c.py` で実行し、標準ライブラリだけを使います。
velk の実行時依存関係は増えていません。

配列レイアウトの共有のテストでは、復元処理が採用したレイアウトを使い、
64 ビットのベースアドレスと添字を記号変数として、倍率付きアドレスの等価性を検証します。
C のコンパイル・実行テストで、構造体サイズ、フィールド位置、バイト単位の書き込みを別途確認します。
SMT 検証は C のポインタの有効性をモデル化せず、ソースのオブジェクト型も推定しません。

文字列の自動復元では、既知ビットから書き込み先の各バイトを取り出す処理を、
各バイト位置の記号入力で検証します。メモリーマッピングと復号関数の制御フローは
このビットベクトルの検証には含めず、実行テストで確認します。

[一覧](../tests/smt_inventory.tsv) は、書き換え群について、ソース位置、
適用条件、ビット幅、検証状況を記録しています。記号的なテンプレートや具体的な
パラメータの検証、未検証または部分的な検証、等価変換ではない非決定的な値の
精緻化を区別しています。これは一覧の行数であり、個々の分岐数や全規則の
普遍的な証明数ではありません。一覧はすべての式変換を網羅する証明書ではありません。

ARM32 では、キャリー付き演算のゼロ・符号・キャリー・オーバーフローフラグ、
キャリーを通した回転の値とフラグ、即値シフトの
キャリー抽出、積和を含む長整数乗算を記号的に検証します。ワード結合と
入れ子のフレームオフセットも記号的に検証します。フレームの別名同士の減算は、
実際のフレーム正規化パスを通して検証します。呼び出し、ABI 上の配置、バイナリの
リテラル読み込み、フレームのアラインメント、一般的な制御フローは未検証です。
復元したフレームオブジェクトのオフセットは、i386、x86-64、AArch64、ARM32 で
アドレスを記号的に検証します。配列ループの C 出力が一つのオブジェクトを使うことを
確認し、コンパイルして元の C ソースと戻り値を比較します。C のポインタの由来は
SMT モデルの対象外です。

## 検証の優先順位と追加した証明条件

次の順序は、一覧の未検証・部分検証の群と、以下で検証する ARM32 の群を順位付けしたものです。
同じ行の群は同順位です。正しさを確認する順序であり、不具合頻度の測定ではありません。
残る未検証範囲は一覧に記録します。群名は一覧の英語表記に対応します。

| 優先順位と理由 | 一覧の群 |
| --- | --- |
| 1. 演算・比較・フラグ：値や分岐の誤りが結果を変えます。 | Integer and vector constant folding; Recover overwritten comparison operand; Carry arithmetic and flags; Remove conditions fixed by dominating guards |
| 2. キャスト・拡張・要求幅：符号の解釈と捨てるビットが C の結果に影響します。 | Remove redundant low32 view; Specialize variables to32 and drop masks; Remove masks/extensions and replace singletons; Narrow to demanded low bits; Division/remainder casts; Omit integer/float conversion casts; Fit return/argument type; Narrow assignment spelling; Narrow printed locals |
| 3. シフト：入力キャリーは結果のビットと出力キャリーに影響します。 | Rotate through carry |
| 4. 除算の形：認識した命令列と整数の証明条件を接続する必要があります。 | Unsigned reciprocal multiply/shift; Signed high-product quotient; Unsigned high-product quotient; Signed widening quotient; Named widening-product quotient; Multiply-back remainder chain; Following multiply/subtract remainder; Accept quotient equivalence; Accept remainder equivalence |
| 5. アドレスとメモリ：オブジェクト、別名、フレームの事実が必要です。 | Remove unsigned-load mask; Store-to-load forwarding; Fuse load/op/store; Forward spilled variables; Replace frame pointer; Scale pointer arithmetic and spell negative offsets; Select common type/casts; Fold byte pointer arithmetic; Replace raw load by named access; Promote saved parameters; Stack addresses to array offsets; ABI object access to local object; Fold structure scales/indexes; Read immutable literal bytes; Normalize word frame addresses and aliases; Known-bit extraction into stored bytes |
| 6. その他の副作用・制御フロー・浮動小数点式：有限のスカラーテンプレートでは証明できません。 | Identical-operand sub/xor/and/or; Recursive expression substitution; Remove single-use definition; Inline local copy; Inline into only reader; Share repeated expression; Fold SSA assignments and branches; Remove floating mask; Drop update masks; Substitute returned copy; Inline values into structured nodes; Pair calls and results; Runtime division remainder; Find redundant copies across blocks; Replace redundant structured copies; Drop unused argument-register result bindings; Permute x86 scratch registers for signature matching |

追加した検証は実際の命令変換、簡約器、剰余の認識を呼び出します。

- ARM32 ADC/SBC/RSC の 64 ビット IR レジスタへゼロ拡張した 32 ビットの結果を、剰余演算による和・差と比較します。
  オーバーフローは、入力キャリーまたはボローを含む
  符号付き 64 ビットの厳密な和・差を 32 ビットの符号付き範囲と比較します。
  全 32 ビットオペランドと両方の入力キャリー値を記号変数にします。
  入力キャリー・ボローの欠落、結果の切り詰めの欠落、NZCV の反転を誤った変種として検出します。
- ARM32 RRX の 32 ビット結果は、入力キャリーと入力のビット 31〜1 の連結と比較します。
  保存した NZCV はそれぞれ独立した記号変数です。64 ビット IR レジスタの上位が 0 であることも検証します。
  NZC の更新と V の保存、S なしの場合の全フラグ保存を検証します。
  キャリーの欠落とフラグ反転を誤った変種として検出します。入力キャリー不明時は変換を拒否します。
- 剰余の走査は 32/64 ビットの符号付き・符号なし入力、除数 2/8/128/2^30、
  商のコピーと乗算による引き戻しを対象とします。後続剰余は定数とレジスタに格納した乗数を扱います。
  実装の等価性検査が置換を受理することと、記号実行による戻り値・定義条件の一致を確認します。
  誤った除数と剰余の符号反転を誤った変種として検出します。商から始まるテンプレートであり、
  逆数乗算との統合とシフト加算の走査は未検証です。
- 全 32 ビットの符号なし入力を乗数 2^31 で 64 ビット乗算し、32/33/40/61/63 ビット右シフトします。
  実際の簡約器が 2^(shift-31) による除算を出力することと式の等価性を確認します。
  除数を半分にした変種を検出します。2 の累乗以外の全幅の合成的証明は未検証です。

ARM32 のテンプレートは、入力式とフラグ式で読むすべてのレジスタとは別のレジスタに結果を代入します。
代入先が入力と同じ場合の値の保存は、このテンプレートでは検証しません。

`Proofs::counterexample` は意図的に誤らせた等式に SAT を要求し、UNSAT または
ソルバーの上限到達で失敗します。等価性の検証は UNSAT を要求します。
同一のクエリは期待する結果も同じ場合だけ共有します。追加した検証には誤った変種を併記しますが、
既存の全検証に併記しているわけではありません。
COM の vtable の読み込みを式に置き換える検証は、Windows の両フィクスチャで
実際の出力準備処理を実行し、入力レジスタとバイト配列のメモリを記号化します。
観測するのは呼び出し前の間接的な呼び出し先です。メソッドの ABI の一致は、
この等価性の検証ではなく、コンパイルして実行するテストで確認します。

## 実装との対応

テストは簡約コンストラクタを使わずに入力の式木を作り、実際の Rust コンストラクタ
またはパスを呼び出します。変換前後を SMT に翻訳し、レジスタ入力は記号変数のまま
検証します。比較や符号付き演算の意味は推論されたオペランド幅に依存するため、
それらを外側に置いた式全体も、実際のパスを通して検証します。
値と推論幅の両方が同じなら、スカラー式の内部でも合同性により等価です。
追加の周辺式の検証は幅が変わる場合に行います。シフト量ゼロの算術シフトについては、
各推論幅の記号的なフィールドを組み立て、任意の 64 ビット値を対象に検証します。

直線的な命令列では、代入先の切り詰めを含めて記号実行し、実際の 8 種類の最適化
パスの前後を比較します。フラグの検証は、実際に復元された条件を独立したフラグの
数式と比較します。回転とバイト反転は、実際に生成された式をビットベクトルの
回転やバイト抽出と比較します。可変回転量は幅（8/16/32/64）で割った余りごとに
分割して検証します。各クエリは式の生成後に回転量の下位ビットを固定し、上位ビットは
記号的なまま残すため、可変回転量の式を変更せずにすべての 64 ビット回転量を対象にします。
これにより、Z3 4.13.3 で単一の記号的な回転クエリがリソース上限に達する問題を避けます。
定数回転量とバイト反転はそれぞれ独立した証明義務として検証します。
逆数乗算の検証では、Rust が受理した除数を取り出し、
商ごとの区間の不等式を整数演算で証明します。対応する領域のすべての被除数を
対象としますが、乗数、シフト、除数候補の集合は有限です。

スカラー C の検証では、実際のレンダラーで関数を生成します。Clang が C を解析し、
暗黙の整数昇格やキャストを含む型付き AST を提供します。テスト用スクリプトは
AST をビットベクトルと、符号付きオーバーフロー、シフト、除算の有効条件に変換します。
モデル上で IR が有効なら、C も未定義動作を起こさず、同じ値を返す必要があります。
先頭・末尾のゼロ数は 8/16/32/64 ビットについて、ゼロ入力と入力の切り詰めも含めて検証します。
別の Clang/UBSan 回帰テストでは、マスク付き加算、符号反転、負のポインタ添字を
コンパイルして実行します。

一覧の `site` の行番号と[ソースのダイジェスト](../tests/smt_sources.sha256)は、
通常の一覧テストを `VELK_BLESS=1` で実行すると生成されます。各 `anchor` は
対応するソース内で文字列として一度だけ現れる必要があります。
Rust の構文を解析し、アンカー全体を含む最小の関数または match アームを選びます。
関数は属性、シグネチャ、本体を含み、アームは属性、パターン、ガード、本体と、
存在する場合は末尾のコンマを含みます。SHA-256 はその範囲の最初のトークンから
最後のトークンまでのソースのバイト列を対象とし、内部の空白やコメントも含みます。
範囲の外にある先頭のインデントや末尾の空白は含みません。
これらの構文の外にあるアンカーは拒否します。
ダイジェスト一覧はソースパスとアンカーの組ごとに一項目を生成し、その順に並べます。
同じアンカーを共有する行は同じダイジェストを使い、行番号はキーに含めません。
範囲を変更せずに移動した場合は行番号の再生成だけが必要です。
範囲外の編集は確認済み状態に影響しません。Git の union マージドライバーは
一覧とダイジェストの変更を両方残します。マージやリベースの後、次のコマンドで
行を並べ直し、重複を除いて生成します。

```sh
VELK_BLESS=1 cargo test --release --lib inventory -- --test-threads 3
```

マージ時には両方の書き換え群と確認済みの検証範囲を残してください。
各行の `rewrite`、`side_conditions`、`widths`、`coverage`、`anchor`、
`reviewed_sha256` は手作業で管理し、再生成では変更しません。
同じキーに異なる確認済みダイジェストがある場合、現在のソースに一致する行があれば
再生成でその行を残します。どれも一致しなければ両方を残して失敗するため、レビューが
必要です。一致するダイジェストを持つ行同士の競合も手動で解消してください。
再生成なしのテストは重複、順序の違い、古い行を検出します。
ソースを変更した場合は書き換えとテストを確認し、必要なら検証範囲と条件を更新し、
生成されたダイジェスト一覧の該当パスとアンカーの SHA-256 を、
該当行の `reviewed_sha256` に手で転記します。
確認済みダイジェストが不一致なら、再生成モードでも生成ファイルを書いた後に失敗します。
再生成を繰り返してもソース変更が承認された扱いにはなりません。
最後に再生成モードを外して実行し、生成情報と確認情報の両方を検査してください。
この検査は選択した範囲だけが対象です。呼び出すヘルパー、インポートなど範囲外の
依存先は対象外なので、それらを変更した場合もレビューが必要です。
現在の検証範囲は一覧に記録し、この文書には件数を重複して記載しません。

検証対象の出力は毎回実装を呼び出して生成します。実装が変更されても古いまま残る
保存済みの置換式は使用しません。

## モデルと制限

同じバイトで塗りつぶす領域について、1、2、4、8 バイトのストア幅、テストに含まれる
各重なりのオフセット、両方のストア順序を、記号的なバイト配列で検証します。
実際の区間計算ヘルパーを呼び、元のストアと、返された領域を覆うストアを比較します。
初期メモリ、基底アドレス、設定するバイトは記号値です。小さい領域の全列挙と、
表示した C のコンパイル・実行による検証も行います。任意のアドレス式、volatile
アクセス、フォルト、C オブジェクトの由来は証明していません。

IR の演算値は 64 ビットの剰余演算です。狭いレジスタ読み出しはゼロ拡張します。
符号付きシフト、除算、剰余、比較には実際のオペランド幅の計算を使います。
シフト量は下位 6 ビットです。選択式は選ばれた枝だけを評価します。
ゼロ除算の評価が変換によって消える場合も、有効条件の違いとして検出します。

メモリ読み出しには、すべてのアドレスに値のあるリトルエンディアンのバイト配列を
使います。ページフォルト、volatile アクセス、寿命、C ポインタの由来は扱いません。
呼び出し、アトミック操作、任意の制御フロー、ABI オブジェクト変換は
このモデルの対象外です。浮動小数点、ベクトル、命令列マッチャー、正規化器の
拡張範囲と残る不足は下記に記載しています。

バイトごとのビット数の合計は分割して証明します。各バイトのビット数を、
変換前後で共有する任意の 4 ビット関数として抽象化します。実際の個数はこの範囲に
収まります。片方の 64 ビット部分を記号的に検証し、両部分については Rust の出力構造を
確認したうえで、拡張された加算を別に証明します。これにより、ビット単位での
加算の結合則の検証に長い時間を費やさずに済みます。

定数パラメータと式形状の集合は有限です。各 SMT 検証が証明するのは、その形状の
すべての記号レジスタ値であり、任意の定数、式木、周辺プログラム、描画条件ではありません。
各クエリは実時間ではなく Z3 のリソース単位 10,000,000 を上限とするため、
CPU の競合で証明に使える計算量が減ることはありません。
未対応の演算や AST ノードはスキップせず失敗します。SAT またはソルバーの計算量上限への到達も失敗とし、
SMT クエリを `target/` に保存します。このテストだけでは、要求されたリポジトリ全体の
全書き換え規則の証明は成立していません。

## 回帰テストの反例

| 変換 | 反例 | 必要な修正 |
| --- | --- | --- |
| 算術右シフト量ゼロ | 8 ビットの `x = 0x80` で `(x + x) sar 0` は `0`。`0x100` ではない。 | シフトによる切り詰めを残す。 |
| 符号付き演算の内部マスク統合 | `x = 0x80` の `((x & 0xff) & 0xffff) sar 1` は `0x40`。`0xc0` ではない。 | 符号を決めるオペランド幅を維持する。 |
| 代入定数の伝播 | 全ビット 1 を 8 ビット代入後に 64 ビットで読む値は `0xff`。 | 切り詰めた定数を記録する。 |
| マスク付き符号付き加算の C 出力 | 符号付き 32 ビットの `0x40000000 + 0x40000001` は `& 0xff` があってもオーバーフローする。 | 安全性を証明できない場合は符号なし演算にする。 |
| 単項符号反転の C 出力 | `INT64_MIN` の反転は IR では同じ値に戻るが、符号付き C ではオーバーフローする。 | 符号なしで反転し、必要なら 64 ビットの符号付き結果に戻す。 |
| 64 ビット拡張の上位マージ削除 | `((1 << 32) & ~0xffffffff) | 1` の 8 バイト拡張は `0x100000001`。 | 拡張元の全幅のマスクを使う。 |
| 同一の例外発生式の相殺 | `(42 / 0) - (42 / 0)` をゼロにしてはいけない。 | 例外を起こし得る評価を残す。 |

## 拡張したモデルと回帰テスト

非循環の分岐、switch、trap、バイト単位のストアを記号実行し、戻り値、定義条件、
最終メモリを比較します。外部へ渡らないフレーム領域のテストは戻り値と定義条件を
観測し、その領域への書き込みの除去を許します。C の型付き AST の検証には
スカラー変数の宣言、代入、条件分岐を追加しています。

IEEE 単精度・倍精度の定数畳み込みは、最近接偶数丸めの演算と明示的な変換丸めを
SMT 浮動小数点演算で比較します。整数変換の無効値・飽和値も含みます。
比較フラグは NaN を含む任意の IEEE ビット列で検証します。整数・ベクトルの具体例は
レーンの演算、比較、シフト、飽和、カウント、交互配置、拡張、切り詰めを対象とします。
pack、暗号演算、拡張除算は未検証です。飽和と上位積のレーンモデルは 32 ビットを
超える幅を近似せず拒否します。

符号付き 2 の累乗除算のチェーンは実際のパスの前後を比較します。逆数乗算の認識は
出力される商と整数の証明条件を別々に検証し、上位積から証明条件への接続には
合成的証明の不足が残ります。内部正規化には、切り詰め、符号拡張、剰余演算の
オペランドについて独立した記号的検証を追加しています。

| 変換 | 反例 | 修正 |
| --- | --- | --- |
| AArch64 の符号なし全幅拡張 | `UXTX(0x100000000)` がゼロになる。 | 64 ビット全体を保持する。 |
| 符号付き除算・剰余の C 出力 | `INT32_MIN / -1` と `INT64_MIN % -1` が C でオーバーフローする。 | 広い符号付き型で演算して切り詰める。 |
| 狭い商の符号拡張 | 8 ビットの `-128 / -1` を拡張すると `-128` ではなく `128` になる。 | 整数昇格後に狭い符号付き結果を復元する。 |

ゼロカウントの出力も、8 ビットの `clz(254)` が 24 になる問題とゼロ入力の未定義動作を修正しました。
符号なしの元の型へ切り詰め、ゼロ時の結果を指定する Clang の
`__builtin_clzg` / `__builtin_ctzg` を使い、記号的 C 検証と UBSan 実行で確認します。

これらはすべて修正前の実装に対して失敗しました。出力 C の検証は除算を囲む式も対象とし、
UBSan 付きコンパイル・実行テストでは変数の除数による商と剰余も確認します。

次の行は完全に未検証です。証明不可能という意味ではなく、モデルが不足しています。

- 複合代入のマスク除去：スカラー代入は別々の変数に分割され、複合代入のヘルパーを
  実行する例になっていません。
- フレームポインタ置換：保存したフレームポインタの設定と復元は未検証です。
- レンダラーの浮動小数点マスク除去と暗黙の整数・浮動小数点変換：C の AST モデルは
  整数 C を対象とし、浮動小数点式や union によるビット再解釈を扱いません。
- バイトポインタ簡約、名前付きメモリ、保存引数、スタック配列、ABI オブジェクト：
  C オブジェクト、境界、エイリアス、ABI のモデルが必要です。
- 構造体のスケールと添字の簡約：レイアウトの事実を独立して検証する必要があります。

部分的な行の不足範囲は一覧に残しています。一般のループ、呼び出し、アトミック操作、
volatile とフォルトを伴うメモリ、ABI 捕捉、呼び出し側の安全性、一般の範囲・要求ビット、
構造化制御フローは有限の非循環テンプレートでは証明されません。浮動小数点の例外フラグ、
動的丸めモード、プロセッサ固有の NaN ペイロード選択も扱いません。結果が NaN となる
浮動小数点演算の畳み込みは引き続き行いません。

新しい入口は `ir::smt` の `rewrite_tests` と `program`、`division::smt_tests`、
`division::proof::smt_tests`、各アーキテクチャの SMT テスト、
`compiled_assignments_and_return_conversions_are_equivalent` です。
各ソルバーテストは少なくとも 1 件の非自明な証明条件を提出する必要があります。

ビット演算と算術演算を混ぜた式の検査では、実際の正規化と置換候補の探索を
8、16、32、64 ビットで実行します。三つの記号的レジスタ読み取りによる
全 256 種類のブール関数を、各ブール値の割り当てについて共通の記号的な
ビットマスクを使って検査し、線形性によってビット位置ごとの結果を合成します。
和・XOR・OR の線形恒等式、定数の相殺、定数倍、
恒等式を直接検査します。二次式では、証明した和の恒等式と、記号的な多項式の
環の検査を合成します。係数とシフトの具体例で折り返しの境界を扱います。
係数を変えた式、例外を起こしうる入力、対象外のマスク、探索上限を反例として
検査します。対象は有限のテンプレートであり、実装が受理するすべての
多項式の木を証明するものではありません。

配列要素の途中を指すポインタのテストでは、正規化処理を呼び出し、
各ポインタのオフセットを戻したときに、代入とアクセス先アドレスが保存されることを
64 ビットの桁あふれを含めて確認します。部分読み出しと部分書き込みの拒否は別のテストで確認します。
