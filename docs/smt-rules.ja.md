# 式の等価性テスト

通常の Rust 単体テストには、テスト専用の Z3 検証が含まれます。
`cargo test --release --lib smt -- --test-threads 3 --nocapture` で実行できます。
PATH に Z3 が必要です。存在しない場合は明確なスキップ理由を表示します。
C 出力の検証には Clang と uv も必要です。Python は
`uv run --no-project tests/smt_c.py` で実行し、標準ライブラリだけを使います。
velk の実行時依存関係は増えていません。

[一覧](../tests/smt_inventory.tsv) は、134 の書き換え群について、ソース位置、
適用条件、ビット幅、検証状況を記録しています。記号的なテンプレートや具体的な
パラメータの検証、未検証または部分的な検証、等価変換ではない非決定的な値の
精緻化を区別しています。これは一覧の行数であり、個々の分岐数や全規則の
普遍的な証明数ではありません。一覧はすべての式変換を網羅する証明書ではありません。

ARM32 では、キャリー付き演算のゼロ・符号・キャリーフラグ、即値シフトの
キャリー抽出、積和を含む長整数乗算を記号的に検証します。ワード結合と
入れ子のフレームオフセットも記号的に検証します。フレームの別名同士の減算は、
実際のフレーム正規化パスを通して検証します。呼び出し、ABI 上の配置、バイナリの
リテラル読み込み、フレームのアラインメント、一般的な制御フローは未検証です。

## 実装との対応

テストは簡約コンストラクタを使わずに入力の式木を作り、実際の Rust コンストラクタ
またはパスを呼び出します。変換前後を SMT に翻訳し、レジスタ入力は記号変数のまま
検証します。比較や符号付き演算の意味は推論されたオペランド幅に依存するため、
それらを外側に置いた式全体も、実際のパスを通して検証します。
値と推論幅の両方が同じなら、スカラー式の内部でも合同性により等価です。
追加の周辺式の検証は幅が変わる場合に行います。シフト量ゼロの算術シフトについては、
各推論幅の記号的なフィールドを組み立て、任意の 64 ビット値を対象に検証します。

直線的な命令列では、代入先の切り詰めを含めて記号実行し、実際の 8 種類の最適化
パスの前後を比較します。フラグの検証は、実際に復元された条件を独立したフラグの
数式と比較します。回転とバイト反転は、実際に生成された式をビットベクトルの
回転やバイト抽出と比較します。逆数乗算の検証では、Rust が受理した除数を取り出し、
商ごとの区間の不等式を整数演算で証明します。対応する領域のすべての被除数を
対象としますが、乗数、シフト、除数候補の集合は有限です。

スカラー C の検証では、実際のレンダラーで関数を生成します。Clang が C を解析し、
暗黙の整数昇格やキャストを含む型付き AST を提供します。テスト用スクリプトは
AST をビットベクトルと、符号付きオーバーフロー、シフト、除算の有効条件に変換します。
モデル上で IR が有効なら、C も未定義動作を起こさず、同じ値を返す必要があります。
先頭・末尾のゼロ数は 8/16/32/64 ビットについて、ゼロ入力と入力の切り詰めも含めて検証します。
別の Clang/UBSan 回帰テストでは、マスク付き加算、符号反転、負のポインタ添字を
コンパイルして実行します。

通常の単体テストはソース位置と[ダイジェスト](../tests/smt_sources.sha256)も確認します。
一覧にあるソースを変更した際は、一覧と検証範囲の明示的な見直しが必要です。
検証対象の出力は毎回実装を呼び出して生成します。実装が変更されても古いまま残る
保存済みの置換式は使用しません。

## モデルと制限

IR の演算値は 64 ビットの剰余演算です。狭いレジスタ読み出しはゼロ拡張します。
符号付きシフト、除算、剰余、比較には実際のオペランド幅の計算を使います。
シフト量は下位 6 ビットです。選択式は選ばれた枝だけを評価します。
ゼロ除算の評価が変換によって消える場合も、有効条件の違いとして検出します。

メモリ読み出しには、すべてのアドレスに値のあるリトルエンディアンのバイト配列を
使います。ページフォルト、volatile アクセス、寿命、C ポインタの由来は扱いません。
ストア、呼び出し、アトミック操作、任意の制御フロー、ABI オブジェクト変換も
このモデルの対象外です。浮動小数点と多くのベクトル演算も未検証です。
より豊かなモデルで表現可能なため、本質的に証明不能とは分類していません。
逆数の証明は、除算の命令列マッチャーや内部の正規化器の証明を含みません。

バイトごとのビット数の合計は分割して証明します。各バイトのビット数を、
変換前後で共有する任意の 4 ビット関数として抽象化します。実際の個数はこの範囲に
収まります。片方の 64 ビット部分を記号的に検証し、両部分については Rust の出力構造を
確認したうえで、拡張された加算を別に証明します。これにより、ビット単位での
加算の結合則の検証に長い時間を費やさずに済みます。

定数パラメータと式形状の集合は有限です。各 SMT 検証が証明するのは、その形状の
すべての記号レジスタ値であり、任意の定数、式木、周辺プログラム、描画条件ではありません。
未対応の演算や AST ノードはスキップせず失敗します。SAT またはタイムアウトも失敗とし、
SMT クエリを `target/` に保存します。このテストだけでは、要求されたリポジトリ全体の
全書き換え規則の証明は成立していません。

## 回帰テストの反例

| 変換 | 反例 | 必要な修正 |
| --- | --- | --- |
| 算術右シフト量ゼロ | 8 ビットの `x = 0x80` で `(x + x) sar 0` は `0`。`0x100` ではない。 | シフトによる切り詰めを残す。 |
| 符号付き演算の内部マスク統合 | `x = 0x80` の `((x & 0xff) & 0xffff) sar 1` は `0x40`。`0xc0` ではない。 | 符号を決めるオペランド幅を維持する。 |
| 代入定数の伝播 | 全ビット 1 を 8 ビット代入後に 64 ビットで読む値は `0xff`。 | 切り詰めた定数を記録する。 |
| マスク付き符号付き加算の C 出力 | 符号付き 32 ビットの `0x40000000 + 0x40000001` は `& 0xff` があってもオーバーフローする。 | 安全性を証明できない場合は符号なし演算にする。 |
| 単項符号反転の C 出力 | `INT64_MIN` の反転は IR では同じ値に戻るが、符号付き C ではオーバーフローする。 | 符号なしで反転し、必要なら 64 ビットの符号付き結果に戻す。 |
| 64 ビット拡張の上位マージ削除 | `((1 << 32) & ~0xffffffff) | 1` の 8 バイト拡張は `0x100000001`。 | 拡張元の全幅のマスクを使う。 |
| 同一の例外発生式の相殺 | `(42 / 0) - (42 / 0)` をゼロにしてはいけない。 | 例外を起こし得る評価を残す。 |
