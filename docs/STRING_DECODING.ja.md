# 文字列の自動復元

[English](STRING_DECODING.md) | 日本語

IR インタープリターで読み込んだ命令を実行し、バッファーのポインターと、その後に
渡される既知のバイト数を持つ呼び出し、およびバッファーを使う呼び出しの前にある
インラインの書き込みを調べます。復号関数の名前では候補を選びません。結果は文字列と
機械命令のアドレスを含むコメントです。同じ関数への呼び出しが複数ある場合は、
一意な名前付きバッファーで呼び出しを識別します。識別できなければ、描画用の IR に
命令アドレスが残らないため、特定の呼び出しには付けず関数の後に表示します。
命令、呼び出し、データをコメントで置き換えることはありません。

```sh
velk --strings app.elf --contains sample
velk -D app.elf case_xor
velk --strings app.elf --no-string-decoding
velk -D app.elf case_xor --no-string-decoding
```

`strings` 配列にはファイル内の文字列を残します。`decodedStrings` 配列には復元した
文字列、`addr`（出力バッファー）、`function`（呼び出し元）、`site`（復号の呼び出し、
またはその後のバッファー使用位置）、`decoder`、`decoderName`、`stack`、`encoding`
および既知の長さの次にある定数引数（`key`、存在する場合）を含めます。
`decodedConfigurations` には 2 個以上の文字列または整数フィールドを持ち、トークン化、
整数変換、または書式付きスキャン関数にバッファー内のポインターが渡された
JSON または区切り付きのキーと値のバッファーを含めます。`evidence` には確認した関数名を
記録し、復号関数と呼び出し位置の情報も付けます。
JSON のオブジェクトパスはドットで連結し、配列には添字を付けます。スタックとヒープの
アドレスは実行中のプロセスではなくエミュレーター内の値です。`--contains` は各配列の
復元テキストで絞り込みます。

共通関数 `velk::string_decoding::configurations` は復元した文字列から同じフィールドを
抽出し、インジケーター抽出など他の解析でも使えます。
`decodedStrings` の `evidence` にも、バッファー内のポインターを受け取った解析関数名を記録します。

```js
const b = velk.open("app.elf");
b.strings({contains: "sample"}).decodedStrings;
```

```js
const b = velk.open("app.elf");
b.strings({decode: false}).decodedStrings;
```

```js
const b = velk.open("app.elf");
b.getFunction("case_xor").decompile({decodeStrings: false});
```

MCP では `velk_run_script` から同じ JavaScript の操作を使えます。フィールドや
オプションは `velk_read_api` で確認できます。

## 採用条件と上限

復元中、レジスターと未初期化のスタックやヒープのバイトは未知として扱います。
データ領域はゼロで初期化される領域も含めてファイルの初期状態から始めます。
関数の先頭より前の実行や、以前の呼び出しによる書き込みは再現しません。
未知の分岐や入力、未対応命令、トラップ、扱えない呼び出し、上限への到達で実行を
止めます。復号結果には正常なリターンと、引数のバッファー、ローカルスタック、
値渡しのスタック引数だけへの書き込みを要求します。戻り先は既知で変更されていない
必要があります。復号関数が正常に戻れば、呼び出し元がその後停止しても
結果を記録できます。インラインの結果はバッファーを次の呼び出しに渡す直前に記録し、
その呼び出しの動作を省略したり推測したりはしません。

文字列には既知の終端、4 文字以上、妥当な UTF-8 またはリトルエンディアンの UTF-16
を要求します。タブと改行以外の制御文字は認めません。変換されたバイトを必要とします。
バイト数の直後にある既知のゼロバイト（UTF-16 ではゼロのコード単位）も終端として
認めます。出力バッファー内で復元した文字列の終端より後にも書き込む場合は採用しません。
スタック上に 1 バイトずつ組み立てた定数も、C の文字列操作（`puts`、`strlen`、
`strcmp`、`strncmp`、`strcpy`）で使う場合に採用します。通常のバイトコピーは対象外です。

各関数は 200000 文までです。追跡する書き込み領域
は 64 KiB、バイト書き込みは 200000 回、出力バッファーは 4096 バイト、結果は各関数
64 件までです。バイナリー全体の文字列探索はすべての関数を調べます。インタープリターの
コード量と呼び出し深度の上限も適用します。呼び出し元の期限は実行と命令の持ち上げの区切りで確認し、
結果は関数ごとにキャッシュします。上限により見逃す場合があります。Go の呼び出し規約、
未知の長さ、終端のないバッファー、4 文字未満の文字列は復元しません。

## 使用例の再現

`sh tests/make_string_decoding_fixtures.sh` で例の関数を
`target/string-decoding-fixtures/` にビルドします。上の `app.elf` を
`target/string-decoding-fixtures/x86_64.O0.elf` に置き換えてください。
`cargo test --release --test string_decoding -- --test-threads 3 --nocapture` は
復元結果をソースおよびネイティブ実行と比較し、方式とアーキテクチャごとに
発見数・誤検出数・見逃し数を表示し、シェルと JavaScript の使用例を実行します。
