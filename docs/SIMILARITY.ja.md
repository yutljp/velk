# 関数の類似度

```sh
velk --similar pair_sum tests/fixtures/arm64.o --in tests/fixtures/arm64_macho.o --limit 5 --json
velk --similar pair_sum tests/fixtures/arm64.o --limit 3
```

```js
const b = velk.open("tests/fixtures/arm64.o", {cache: false});
const other = velk.open("tests/fixtures/arm64_macho.o", {cache: false});
b.getFunction("pair_sum").similar({in: other, limit: 5});
```

MCP の `velk_run_script` でも同じ JavaScript を使えます。
`in` / `--in` を省略すると、同じバイナリ内で元の関数のアドレスを除いて検索します。
検索先を明示した場合は同じアドレスも含みます。件数の既定値は 10、0 は候補なしです。
JSON と JavaScript は `{matches, failures}` を返します。各候補は `function`、
`score`、6 個の `evidence` を含みます。テキスト表示も各特徴のスコアと共通トークンを
表示します。JSON のアドレスは 64 ビットを保持する文字列です。

## スコア

各特徴について、多重集合の Jaccard 係数を計算します。トークンごとの出現数の小さい方を
合計し、大きい方の合計で割ります。両方が空なら 0 です。固定の重みで加算します。

| 特徴 | 重み | トークン |
| --- | ---: | --- |
| CFG | 0.15 | ブロック数、辺数、自然ループのヘッダー数、入次数と出次数の組の頻度 |
| 呼び出し | 0.20 | 解決された呼び出し先のデマングル済みの名前の集合 |
| 定数 | 0.25 | ロードされたセクション外の IR 定数の集合 |
| 文字列 | 0.20 | 参照索引が持つ参照先文字列の集合 |
| 演算 | 0.15 | IR 文の種類、二項演算、適用演算、ロード、拡張、選択の多重集合 |
| プロトタイプ | 0.05 | 復元した戻り値の型、引数の型の並び、可変長引数の有無を含む 1 トークン |

CFG は例外辺も含みます。自然ループのヘッダーは、辺の始点を支配する終点です。
CFG と演算にはブロックアドレスやレジスタ番号を使いません。プロトタイプには
引数名と呼び出し規約を使いません。関数自身の名前は一致の特徴ではありませんが、
呼び出し先の名前は使います。プロトタイプはプロジェクトの型指定を適用する前の解析結果です。
逆コンパイル時の文字列復元結果は索引の特徴に追加しません。

スコアの範囲は [0, 1] です。呼び出しや文字列がないことには加点せず、他の重みも
増やしません。そのため同一の末端関数でも 1 未満になることがあります。
根拠には重み、重なりの係数、辞書順で最大 16 個の共通トークンを示します。
スコアの計算にはすべてのトークンを使います。スコアの降順、同点ならアドレスの昇順です。
スコアの下限による除外はありません。

これは検索候補であり、動作の等価性、ソースの同一性、安全性の証明ではありません。
小さな無関係の関数でも構造や型が一致します。最適化、インライン化、ベクトル化、
未解決の呼び出し、シンボルの削除、型推論の誤りは順位を変えます。
低いスコアも動作が異なることの証明ではありません。編集の判断に使う前に C と命令を確認してください。

## 索引とライブラリ

`Binary::similar(addr, limit, deadline)` は同じバイナリ内を検索します。
`similar::search(&mut source, addr, &mut destination, limit, deadline)` は別のバイナリを検索します。
繰り返し検索する場合は `Binary::similarity_index` を取得し、`Index::features` で
元の特徴をコピーして `Index::search` に渡せます。

最初の要求で、開いたバイナリごとに一度だけ特徴の索引を作ります。既存の関数解析
キャッシュと参照索引を再利用します。以降の検索はリフトを行いません。特徴索引は
セッション内に保持し、サイドカーのキャッシュには保存しません。プロジェクトと
シグネチャの変更で無効になります。中断した索引は保存しません。解析に失敗した
関数は候補から除外し、アドレスとともに報告します。元の関数の解析失敗はエラーです。
大きなバイナリでは索引作成が MCP の既定の制限時間を超えることがあるため、必要に応じて
`timeout_ms` を増やしてください。既存の索引の検索でも期限を確認します。

## 検証

`tests/similar.rs` は `tests/fixtures/metrics` と `tests/fixtures/arm32` 内の
各 C ソースについて、全方向のバリアント対で 1 位と 5 位以内の正解率を計測します。
正解には関数シンボルを使い、シンボルを除いた重複ファイルは対象外です。
最適化、アーキテクチャ、形式の違いを含みます。両方に名前が存在し、解析できた関数だけを
クエリとして数えます。対の数と正解率の分子・分母を表示します。
また、ループのソースを `clang` と `cc` の `-O0` と `-O2` でコンパイルし、
全方向の対を評価します。コンパイラのバージョンも表示します。
環境によっては `cc` が `clang` と同じコンパイラを指す場合があります。

テストは決定的な順序、値の範囲、無関係な演算、アドレスの正規化、5,000 候補の索引、
ライブラリ・CLI・JavaScript・MCP の一致を確認します。上のコマンドとスクリプトも
ドキュメントのテストで実行します。出力 C の計算を書き換えないため、SMT の書き換え規則は追加しません。
