# ビット演算と算術演算を混ぜた式

既定の解析では、`(x ^ y) + 2 * (x & y)` を `x + y` に、
`x + y - 2 * (x & y)` を `x ^ y` に、
`(x | y) + (x & y) - y` を `x` に簡略化します。
定数の相殺、定数倍、これらの和の積も、同じ正規化で扱います。

ビット演算を AND 項の整数和で表し、64 ビットの折り返し演算で
多項式の係数をまとめます。短い式を採用する前に、係数の対応が完全に
一致することを確認します。候補は展開した多項式、個々のレジスタ、
そのビット反転、レジスタの組に対する二項の算術演算とビット演算です。
探索には上限があり、常に最短の式が得られるわけではありません。

対象は、異なるレジスタ読み取りが三つ以内で、その幅が 8、16、32、64
ビットの式です。整数定数、加算、減算、乗算、定数による左シフトを扱います。
AND、OR、XOR の項に含められるのは、レジスタとゼロおよび全ビットが 1 の
定数です。これらの項に含まれる任意のビットマスク、メモリ読み取り、除算、
右シフト、機械固有の演算は対象外です。ノード数 192、深さ 32、多項式の項数 32、
次数 4 を上限とします。式全体が対象外でも、対象となる部分式は簡略化できます。
符号付き演算の意味が幅に依存するため、式の内部と比較では幅を維持します。
ビット演算が反転だけの場合は、結果が定数またはレジスタになる簡略化だけを
採用し、`base + (~index) * size + offset` のような配列の添字の形を保ちます。
通常の解析ではソルバーを実行しません。

CLI の関数カード（`velk --card app mba_add`）、JavaScript の関数カードと
サマリ、MCP 経由のスクリプトは
`simplification.mbaExpressionsSimplified` を返します。
これは解析中に採用した式の置換の数です。ソース関数の数でも、コンパイラが
すでに除去した恒等式の数でもありません。式、条件分岐、ディスパッチャの
いずれかを簡略化すると `simplified` が true になります。

```javascript
const f = velk.open("app").getFunction("mba_add");
[f.card().simplification, f.summary().simplification]
```

フィクスチャのソースは `tests/cases/mba/expressions.c` です。
`sh tests/scripts/make_mba_fixtures.sh` は Clang を使い、x86-64 と AArch64 の
オブジェクトを `-O0` と `-O2` で生成します。
`cargo test --release --test mba -- --test-threads 3` は出力した C を
両方の最適化水準でコンパイルし、境界値を含む入力について、ネイティブで
実行するソースと独立した符号なし整数の式との一致を検査します。
CLI、JavaScript、MCP のデータも同じテストで検査します。
[SMT の一覧](SMT_RULES.ja.md) に、記号的検査の範囲と制限を記載しています。
