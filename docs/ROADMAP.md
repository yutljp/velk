# ロードマップ

velk が目指す設計と、そこへ進む順序をまとめたものです。逆コンパイルの各問題について、
知られている手法の弱点を越えることを目標にします。各項目は、既存の検査
（動作の比較、正解率、難易度別の期待値）で改善を測れる単位に分けて進めます。

## 1. 関数の境界

**済**: noreturn を呼び出し先の制御フローから証明する（呼び出し側の様子から推すと、普通に戻る関数を誤って noreturn にする）。unwind 表を主な情報源にし、コンパイラが関数から分離したコード（コールド部分）を見分けて元の関数に取り込む。PLT のスタブに名前を付ける。末尾呼び出しを厳密に判定する（ジャンプ時点のスタックの高さが入口と同じで、飛び先が関数の先頭のときだけ。高さは unwind 表から、なければ追跡したスタックポインタから得る。それ以外の飛び先はこの関数のフレームのまま続くコードとして取り込む）。

**次**:
- unwind 表を持たないコードのために、リロケーションとデータの中のコードへのポインタを集める。
- AArch64 の `bti c` / `paciasp` を関数の入口の手がかりにする（`bti j` は関数の中にも現れる）。

## 2. 命令の意味

**目標**: 命令の意味を、手で書くのではなく機械可読な仕様と形式的な意味論から生成し、実機で差分検証する。

- 生成元は、再配布と派生物の公開を許すライセンスのものに限る。
- 差分検証: 命令列をランダムな状態で実機実行し、lift した IR の実行結果と比べる。
  CPU が未定義とするフラグは比較から外す。
  - AArch64 のデータ処理命令と、x86-64 のレジスタとフラグだけを使う命令は実装済み（`src/lift/hardware/`）。
    フラグを立てる命令と読む命令の組み合わせも含めて、全ケースが実機と一致する。
  - 残り: ロード・ストア、分岐、浮動小数とベクトル。
- 浮動小数とベクトルは、意味を宣言した専用の演算として持つ。xmm の部分書き込み
  （レジスタからの `movss` は上位を残し、メモリからは上位を 0 にする、AArch64 のスカラー書き込みは上位を 0 にする）を
  明示的に表す。
  - x86-64 と AArch64 のスカラー演算・積和・変換・比較、AArch64 のベクトルレジスタのロード・ストアと要素の移動は実装済み。
    引数と戻り値の浮動小数点、浮動小数点を指すポインタも、デバッグ情報がなくても推定する。
  - 実機との照合は浮動小数点レジスタとスカラーの浮動小数点命令を含み、全ケースが一致する。
  - 丸めモードを指定する変換と、整数・浮動小数点のベクトル演算の主なもの（SSE の整数とパック、AArch64 の加減乗算・比較・
    総和・複製・シフト・`ext`、広げる・狭める変換（`sxtl`、`xtn`、`shrn`）、長い乗算と積和（`smull`、`mla`、`umlal`）、
    並べ替え（`zip`、`uzp`、`trn`）、浮動小数点のベクトル演算と整数との変換）も実装済みで、実機と一致する。
  - ロード・ストアとメモリオペランドも両 ISA で実機と照合し、全ケースが一致する。
  - 残り: 分岐、AArch64 の飽和するシフトと 2 倍して飽和する乗算（`sqshl`、`sqdmulh`）、半精度の浮動小数点、
    浮動小数点の最大・最小。

## 3. 中間表現の層

**目標**: 役割の違う層を順に通す。層の間では、変換の前後を実行して動作が変わらないことを確かめ、
各層には守るべき条件を持たせて、パスの後ごとに検査する。

1. **機械に近い層**（命令の意味）
   - レジスタのバイト範囲・フラグ・メモリといった「場所」への読み書きとして、命令の意味をそのまま表す。SSA ではない。
   - すべてのオペランドが幅を持ち、拡張・切り詰めを明示する。フラグは個別の値として計算する。
   - レジスタはバイト・レーン単位で扱い、`al` / `ah` や xmm の一部を統一して表す。
   - 命令の意味の生成と、実機との差分検証はこの層で行う（第 2 節）。
2. **SSA の層**（解析と最適化）
   - 機械に近い層を SSA に変換する。値に名前があり、φ と定義・使用の関係を持つ。
   - アドレスが外へ漏れないことを証明したスタックスロットも SSA の値にする。
   - 使われないフラグの計算はここで消える。定数伝播・値域・型推論・関数間の要約もこの層で行う（第 4・5 節）。
   - 演算ごとに「消してよいか」「メモリを読むか」などの性質を表で持ち、変換はそれに従う。
3. **変数と式の木の層**（C への変換）
   - SSA から抜けて、値を生存範囲ごとに変数へ割り当てる。変数は引数・戻り値・分割といった役割を持つ。
   - 制御フローを構造化し（第 6 節）、キャスト・メンバアクセス・配列添字への書き換えを行う。
   - 疑似 C はこの木を印字するだけにする。

今の IR は第 1 層に近い役割と第 2 層の最適化を兼ねていて、疑似 C の整形の多くは印字の時点で行っています。
新しい層を作り、既存のパスを 1 つずつ移します。移している間は、今の IR と新しい層を並べて動かし、
同じ関数の結果を比べます。

**済**: SSA の層の土台（構築・整合性の検査・元の IR への戻し。全関数で往復が一致することをテストで確かめる）、
条件付き定数伝播、φ でつながる値による変数の分割。

## 4. 解析

- 値域の根拠を出力に残す（どの分岐がどの値をどの範囲に絞ったか）。持ち上げの段階のジャンプテーブルの範囲判定も
  SSA の値域から行い、直前のブロック以外にある範囲判定に対応する。
- 型推論: 「符号不明」を状態として持つ制約解決にし、部分型を許して、演算と呼び出しグラフを通して伝播させる。
  推測した型と確定した型を区別し、根拠と確度を関数の要約に出す。
- 変数: SSA の値の生存範囲から作り、引数・戻り値・分割といった役割を持たせる（写しでつながり生存範囲が重ならない変数は
  1 つにまとめるようになった。Go のテスト用バイナリの変数は 17278 から 15998 に、行数は 81803 から 78996 に減った）。

**済**: SSA の層の既知ビットと値域（`ssa/ranges.rs`）。分岐の辺で狭め、ループは広げてから狭めて不動点を求める。
値がすでに収まるマスクの省略、範囲で決まる分岐の削除、switch の添字がとらない case と default の削除に使い、
`simplify` と出力の局所的なビットの推論、ジャンプテーブルの添字の上限も同じ伝達関数に置き換えた。
fixture 全体で、最適化の最後に 2429 個、変数の分割の後に 250 個のマスクを除き、分岐 213 個と switch の default 85 個を
除いた。疑似 C は Go で 296 行・31 変数・50 個の trap（範囲検査の panic）、Rust で 333 行・93 変数・73 キャスト・
15 個の trap が減った。
**済**: 変数（汎用レジスタ、ベクトルレジスタの各半分、データを持つフレームポインタ）の型を使われ方から決めて宣言する。
デバッグ情報のないポインタ引数の固定オフセットのアクセスから構造体を定義する。型付きポインタの演算を要素単位で書き、
割り切れないときはバイト単位に直して、疑似 C を C として読んでも値が変わらないようにした。
ベクトルレジスタへの読み込みで、整数のレーンとして使われる配列を浮動小数点の配列と取り違えていた誤りを直した。
引数がどのレジスタとスタックスロットにあるかを経路ごとのデータフローで追い（最適化なしのコードは引数をスタックに置き、
同じレジスタを別の値に使い回す）、ポインタ引数の正解率を -O0 で 83% から 97% に上げた。浮動小数点の戻り値の精度を、
各経路で最後に書いた値から決める（以前は途中の読み込みを見て `float` を `double` としていた）。
戻り値の有無を呼び出し元の使い方からも決め、x86-64 -O0 の正解率を 126/148 から 142/148 に上げた。
スタック上のローカルにも、使われ方から浮動小数点・ポインタの型と符号を与える（最適化なしのコードで効く）。
デバッグ情報なしで、レジスタに収まらない引数をスタックから復元し、呼び出し側もその値を引数として出す
（引数の個数は全構成で 147/147）。SysV でレジスタが余っているのにスタックで渡す引数は、値渡しの構造体として 1 つの引数にし、
構造体を返す関数が受け取る隠しポインタは `result` と名付けて、ソースの引数に数えない。
Go の関数の先頭のスタック伸長の検査を取り除く。末尾呼び出しだけで返す関数の戻り値の幅を呼び出し先から決める。
要約に 32 ビットの値だけを返すかを持たせ、相互再帰の関数（is_odd と is_even など）の戻り値を 32 ビットに決める。
浮動小数点の引数の数も要約に持ち、呼び出しの引数として名前で渡す（以前は整数引数の数に混ざっていた）。
2 つ目以降の戻り値（rdx、Go の後続の戻り値）も変数に移す。呼び出しをまたいで退避した引数は、出力では引数のまま読む。
Go の ABI（xmm15 は常に 0、r14 の g は呼び出しで変わらない、書き込みバリアは r11 だけを壊す）を扱う。
例外表からランディングパッドを読み、受け取る例外を `exception` と書く。
構造体の配列（一定の間隔の添字と固定オフセットの組、または要素ごとに進むループのポインタ）を、要素の構造体と配列として
`p[i].field_0x8` と書く。別のレジスタに掛けておいた添字もアドレスに戻して使う。
引数でないポインタ変数（呼び出しの戻り値など）も固定オフセットのアクセスから構造体にし、`v->field_0x8` と書く。
Go のテスト用バイナリのキャストは 7579 から 6322 に減った。
関数の要約を並列に求める。呼び出しグラフは見つけた関数をまとめて並列に持ち上げて広げ、強連結成分は呼び出す成分が
決まったものから空いたスレッドで、成分の中は段ごとにまとめて求める。持ち上げの結果を呼び出し先の答えと組にして残し、
要約と逆コンパイルと呼び出し元の解析で使い回す。Go のテスト用バイナリの最初の逆コンパイルは 0.81 秒から 0.23 秒、
Rust では 0.55 秒から 0.23 秒になった（8 コア。結果は問い合わせの順番やスレッドの数によらない）。

**次**:
- 構造体の配列: 添字をループの中で書き換える変数に掛けておくコード（x86-64 -O2 で、ループの後の残りの要素を扱う部分）と、
  要素の途中を指して進むループのポインタを、要素とフィールドとして書く。デバッグ情報の構造体にも大きさを持たせ、
  配列として読む。
- 引数をそのまま返す関数の戻り値に、引数の型を与える。
- 呼び出しの引数と戻り値の型を、呼び出し先の型から伝える（ライブラリと実行時の関数はプロトタイプの型を伝えるようになった。
  本体を持つ関数どうしの間はまだ）。
- ジャンプテーブル: 間接分岐を支配するすべての分岐から値域で範囲を求め、各エントリの飛び先を検査する。
  `cmov` で選ぶ少数の飛び先にも対応する。（範囲判定のないテーブルは、添字が取りうるビットか、飛び先が関数の中を
  指して次のテーブルに達するまでで大きさを決めるようになった。前のブロックで番地を置いたテーブルも追う。）

## 5. 関数間の層

**済**: 関数ごとの要約（引数の数、noreturn）を、必要になったときに呼び出しグラフの強連結成分ごとに、
呼び出し先から順に不動点まで求める（問い合わせの順によらず同じ結果になる）。呼び出しの引数と戻り値を IR に持たせ、
`v = name(a0, a1)` の形で出す。要約は壊すレジスタも持つ（入口で保存して戻る前に読み戻すレジスタは壊さない）。
呼び出しの後は、呼び出し先が壊さないレジスタは値が残り、壊すレジスタは規約が保つとしていても変わる。
呼び出しが壊して戻り値も置かないレジスタの読み出しは、前の値ではなく未定義の値とする。
読み取り専用のデータの表（関数ポインタ、仮想関数表、トレイトオブジェクト、Go の関数値）から呼び出し先が決まる間接呼び出しを
直接の呼び出しにする。Rust（シンボルなし）の解決できない間接呼び出しは 276 から 186 に減った。

**次**:
- 取り込んだ関数の引数の数を、書式文字列（可変長引数）と `al`（x86-64）から復元する。
- オブジェクトの型を関数をまたいで追い、別の関数で作ったオブジェクトの仮想呼び出しと、Go のインターフェースの呼び出し（itab）も解決する。

## 6. 構造化

**済**: 支配木による構造化を基本にした（アドレス順の構造化は、支配木が深すぎる関数だけに使う）。
入口から届かないコード（例外の着地点など）は別の根の木として後ろに置く。
アドレス順の構造化が、内側のループや switch の中から外側のループを抜ける分岐を 1 段の `break` にしていた誤りを直した。
共有された `return` を分岐の位置に戻し、ループの途中の出口を `if (…) return` にする。構造化の結果をブロックに戻して実行し、
全関数で元の IR と動作が同じことをテストで確かめる（この検査で、以前の構造化にあった誤りも見つけて直した）。
switch の値が同じ case を共有するとき、その case を合流点と数えていた誤りを直した。戻らない関数（パニック）を呼ぶ短いブロックも
分岐の位置に複製し、ジャンプだけのブロックを素通しにした版や、短い共有ブロックを各分岐に複製した版も試して、
ラベルの少ない方を選ぶ。ジャンプテーブルから作った switch は、元の間接ジャンプと同じ所へ行くことをテストで確かめる。
短い return への goto はその文に置き換え、ストアや呼び出しを含む短い共有ブロックも複製し、`else if` を続けて書く。
出口の多いループは、1 つの分岐からしか入らない出口のコードをループの中に置く版も試す。
Go のテスト用バイナリの goto は 1364 から 366 に、Rust（シンボルなし）は 4050 から 2406 に減った。
残った goto を原因ごとに数える分類を作り、多い原因から戻した：別の判定を補うだけの判定を `&&` / `||` の条件にまとめ、
判定を飛び越すように変えられた分岐をその判定に戻し、1 行で書ける return の末尾はどこへでも複製し、
`for (;;)` を判定の位置に合わせて `while` / `do while` にする。goto は Go で 359 から 128 に、Rust（シンボルなし）で
2371 から 1615 に減り、行数も減った。

**次**:
- goto をなくすことを目的にせず、goto を生むコンパイラの変換をさらに元に戻す。残りの多くは、まとめられた return、
  switch の展開などで共有された末尾、出口の多いループ（`structure/classify.rs` で数える）。
- 多段の脱出を、フラグ変数や関数への切り出しではなく、読みやすい形で表す。
