# アーキテクチャ

velk がバイナリを読み、関数ごとの疑似 C を返すまでの流れと、各段の責務をまとめます。
目標とする設計と、そこへの移行計画は [ROADMAP.md](ROADMAP.md) にあります。

```
バイナリ
  │  loader   形式の解析、配置とリロケーション、関数の発見、名前
  ▼
Image（セクション・関数・関数から分離されたコード・データシンボル）
  │  lift     命令を IR の文に。基本ブロックに分割
  ▼
FunctionIr（ブロック・文・式）
  │  analysis 引数と戻り値の推定、ジャンプテーブル
  │  passes   CSE・簡約・除算の復元・フレームの除去・コピー伝播・DCE
  │  ssa      SSA 形式での定数伝播と変数の分割
  │  typing   幅・符号・構造体フィールド・DWARF の型
  ▼
最適化済み FunctionIr
  │  render   構造化（if / ループ / switch）、式と変数の名前付け
  ▼
疑似 C ・ 関数の要約（JSON） ・ IR ・ 逆アセンブル
```

## loader（`src/loader/`）

- `mod.rs`: ELF / PE / COFF / Mach-O を読み、セクションとシンボルから `Image` を作ります。
- `relocate.rs`: リロケータブルオブジェクトの、メモリを占めるセクションをリンカと同じように並べ、
  リロケーションを適用します。これで `.o` の呼び出しやデータ参照、unwind 表の番地が実際の値になります。
  実行ファイルでは、動的ローダが埋めるポインタ（相対リロケーションと、イメージ自身が定義するシンボルへのもの）を
  ロード番地 0 として埋めます。GOT のような、イメージ自身が埋めるポインタを通る呼び出しとジャンプは、
  lifter がその関数への直接の呼び出しとして扱い、関数の要約（引数の数・戻らないか）も使えるようにします。
- 関数の発見は、確かな情報源から順に重ねます。
  1. シンボル表、動的シンボル、PE のエクスポート、エントリポイント
  2. DWARF（`dwarf.rs`）、Go の pclntab（`go.rs`）
  3. unwind 表（`unwind.rs`）。フレーム記述の最初の行が「戻り番地だけを保存した状態」なら関数の入口で、
     その範囲が関数の正確な大きさになります。すでにフレームの中から始まる記述は、
     コンパイラが関数から分離したコード（めったに通らない経路を集めたコールド部分など）として扱います。
     フレーム記述が指す例外表（LSDA）の呼び出し位置表から、ランディングパッドと、そこへ例外が届く
     呼び出しの範囲を読みます。パッドは独立したブロックになり、入口で受け取る例外と選択値を
     `exception` / `selector` として読み、出力ではラベルの前に由来を注記します。呼び出しの範囲の終わりでブロックを区切り、
     そこからパッドへの辺をデータフロー（SSA・生存解析）に持たせるので、パッドの中の値も変数になります
     （構造化はこの辺を使わず、パッドは別の入口のままです）。
  4. PLT（`plt.rs`）。各スタブが参照する GOT のスロットを動的リロケーションと突き合わせ、
     取り込んだ関数の名前を付けます。スタブを通らずに GOT のスロットから直接呼ぶ（またはジャンプする）コードも、
     そのスロットの名前で呼び出しとして表し、プロトタイプから引数と戻り値の型と戻らないかを決めます。
  5. プロローグの走査（`discover.rs`）。上のどれにも覆われない隙間だけを、
     return・末尾ジャンプ・trap の後の最初の命令として探します。
- `symbols.rs`: Rust（v0 / legacy）と C++（Itanium）のデマングル。

## lift（`src/lift/`）

- `x86_64.rs` と `aarch64.rs` が、デコードした命令を IR の文に変換します。
- `mod.rs` は基本ブロックへの分割と、分離されたコードの取り込み（関数の分岐が入るものを続けてデコード）を受け持ちます。
  文を持たない命令（埋め草の `nop` など）だけのブロックは作らず、そこへの分岐は次のブロックへつなぎ直します。
- `exits.rs` は関数の外へ出る分岐を判定します。末尾呼び出しとするのは、分岐の時点のスタックの高さが入口と同じで、
  飛び先が関数の先頭のときだけです。高さは、関数自身と分離されたコードの範囲では unwind 表の行
  （CFA がスタックポインタ + 入口の値。x86-64 は 8、AArch64 は 0）から、表がなければ lift した IR を追って求めます。
  追跡は入口のスタックポインタからの差を持つレジスタの集合で、`mov rsp, rbp` のようにフレームポインタから戻す場合も
  差がわかります。合流で経路の値が食い違えば不明です。
  - 高さが入口と違うまま関数の先頭へ飛ぶ分岐と、ほかの関数の途中へ飛ぶ分岐は、飛び先のコードがこの関数のフレームのまま
    続くものとして、その関数の終わりまでをこの関数の一部としてデコードし直します（最大 4 回）。
  - 高さが不明なときと、関数の範囲の終わりから次の関数へ流れ込むだけのとき（分岐命令ではないとき）は、
    末尾呼び出しとします。
  - 無条件のジャンプはそのブロックの終わりを呼び出しと return に置き換え、条件分岐は呼び出しを持つ別のブロックへ向けます。
  - 解析（`analysis/mod.rs`）が末尾呼び出しとする、メモリから読んだポインタやブロックが書かないレジスタ（そのコピーを含む）を通るジャンプも、
    追跡した高さが入口と違えばジャンプのまま残します。
- 持ち上げの結果は、関数ごとに、呼び出し先について尋ねた要約とその答えと組にして `Image` に残します
  （関数ごとに 2 つまで。呼び出し先を知らずに持ち上げたものと、知って持ち上げたもの）。同じ関数をもう一度持ち上げるとき、
  尋ねたすべての呼び出し先が同じ答えを返すなら、残した結果をそのまま使います。持ち上げが読むのは要約のうち
  呼び出しに要る部分（引数の数、スタック引数、戻らないか、スタックに返す結果）だけで、ほかの部分は渡さないので、
  そこだけが違う持ち上げは同じものとして扱えます。要約を求めるときの持ち上げを、その後の逆コンパイルと
  呼び出し元の解析が使い回します。追加のブロックの開始（ジャンプテーブルの飛び先など）を与える持ち上げは残しません。
- `flags.rs`: フラグを、最後に設定した命令の種類（差・和・論理演算・結果のみ・即値）と
  そのオペランドとして持ちます。条件分岐・条件付き選択・`setcc` が読む条件は、
  その種類に応じて結果を正確に決める比較に変換します（和の桁上がりは `a > ~b`、
  論理演算の後の桁上がりは常に 0 など）。読みやすい形で正確に書ける場合はその形を選びます。
  AArch64 の条件付き比較（`ccmp`）は「前の条件が成り立てばこの比較、そうでなければ即値」として持ち、
  `a && b` の形の条件になります。モデル化していない方法でフラグを変える命令の後は、フラグを不明とします。
- フラグはブロックをまたいで運びます。1 回目の lift で各ブロックの終わりのフラグと、フラグを知らずに読むブロックを求め、
  前方へのデータフロー（フラグに触れないブロックは入ってきたフラグをそのまま渡す）で、合流するすべての経路が同じ形の
  フラグを持つブロックを決めます。2 回目の lift で、フラグを決めたブロックの終わりにオペランドを専用のレジスタへ書き、
  読むブロックはそのレジスタをオペランドとするフラグから始めます。形が合わない合流では不明のままにします。
- xmm レジスタは 64 ビットの半分 2 つ（`xmm0` と `xmm0_hi`）です。浮動小数点の値はビット列のまま持ち、
  単精度は下位 32 ビットに置きます。x86 のスカラー演算は残りのビットを保ち、`ucomisd` は浮動小数点の比較としてフラグに入ります。
  比較の後の条件は、順序なし（NaN）の場合も含めて正確な比較になります（`ja` は `b < a`、`jb` は `!(a >= b)`）。
- AArch64 のベクトルレジスタも 64 ビットの半分 2 つ（`d0`、単精度は `s0`、上半分は `v0_hi`）です。スカラーの書き込みは
  残りのビットを 0 にし、要素の移動（`dup`、`umov`、`ins`）はレーン単位で読み書きします。
- 未対応の命令は、書きうるレジスタ（x86 はデコーダの命令情報、AArch64 はオペランド）を持ちます。その後の値は不明として扱い、
  古い定数が伝播しないようにします。オペランドを解釈できなかった命令も、黙って捨てずに未対応として残します。

## IR（`src/ir/`）

- `Expr`（レジスタ・定数・二項演算・ロード・符号拡張・選択・演算の適用）と
  `Stmt`（代入・ストア・分岐・switch・呼び出し・return・trap・未対応）の木です。
  演算の適用（`Expr::Apply`）は、整数の二項演算以外の演算を引数の並びに適用します。浮動小数点の四則・平方根・
  積和（丸めは 1 回）・比較（成り立てば 1）・整数との変換と、ビットの数え上げ（先頭・末尾の 0、立っているビット）・
  ビット反転、そしてベクトルのレーン単位の演算（加減乗算・比較・最小最大・シフト・先頭の 0 の数え上げ、交互の並べ替え、
  2 倍の幅への拡張と半分の幅への切り詰め、最上位ビットの収集、レーンの総和）です。ベクトルは 64 ビットの半分ごとに扱い、
  並べ替え（`pshufd`、`ext` など）はシフトとマスクで表します。
  範囲外の値の整数への変換は、x86 の結果（最小の符号付き値）と AArch64 の結果（飽和）を区別します。
- `semantics.rs`: 幅と演算の意味。インタプリタ、定数伝播、簡約が同じ定義を使います。NaN を生む定数式は畳みません
  （そのビット列は実行するプロセッサが決めるため）。
- `cfg.rs`: 後続ブロックと生存解析。`visit.rs`: 読み書きするレジスタの列挙と置換。
- `eval.rs`（テスト用）: IR のインタプリタ。最適化の前後を同じ入力で実行して比べます。
  呼び出しは、その呼び出しが書くレジスタ（要約のある呼び出し先なら要約、なければ規約）のうち、
  戻り値を置くレジスタには呼び出しごとのハッシュを、それ以外にはゼロ（未定義の値と同じ）を入れます。

## passes（`src/passes/`）

`passes::optimize` が順に走らせる変換です。

| パス | 内容 |
|---|---|
| `cse` | 文の中で繰り返す部分式を一時変数に |
| `simplify` | 定数畳み込み、恒等式（`x - x` と `x ^ x` は 0）、マスクの整理 |
| `division/` | 定数による乗算・シフトの列を除算・剰余に戻す |
| `frame` / `frame_slots` | フレームポインタと callee-saved の退避を除き、スタックスロットを変数に（ランディングパッドのフレームポインタは、例外を投げた呼び出しの時点の値として読む） |
| `copies` / `memory` | コピー伝播（ブロックの出口で生きているレジスタは残す）、スタックに置いた値の転送 |
| `dce` | 使われない代入と、レジスタを自分自身に写す代入の除去 |
| `coalesce` | 変数から変数への写しでつながり、生存範囲が重ならない変数を 1 つにまとめ、写しを除く（値域から写しが値を変えないとわかるときだけ。ループの次の値を写しの直前まで下げてから比べる）。同じレジスタから分かれた、同じ幅の値の変数も、生存範囲が重ならなければまとめる（アドレスの土台や添字になる変数は、型がほかの値に移るので除く） |
| `widths` | 32 ビットだけで使うレジスタを 32 ビット変数に |
| `read_once` | 1 回だけ読まれる変数の値を、読む文へ直接書きます（`v5 = *(p + 0x8); f(v5);` は `f(*(p + 0x8));`）。変数の分割と型付けの後、解析の最後に走ります。読む文は同じブロックか、そのブロックからしか入らず必ずそこへ進むブロックにあるものに限り、次に代入されるまでとブロックの後で他に読まれないことを確かめます。間の文が値の読むレジスタを書くなら動かしません。メモリを読む値と、除算のように失敗しうる値は、メモリを読み書きする文・呼び出し・扱えない命令を越えて動かしません（間の文のロードも越えません）。浮動小数点の値と構造体へのポインタは名前のまま残します。読みやすさのため、動かす値は 10 ノード、読む側の各被演算子は 16 ノード・深さ 5、分岐の比較は両辺で 10 ノード、呼び出しの引数は合わせて 28 ノードまでにします（スタックのスロットの読み出しは名前 1 つと数えます）。下位 8・16・32 ビットのマスクや、値に収まるマスクと定数との等価比較（`(v & 0x4) != 0`）を通した読み出しは、幅が違っても置き換えます |

最適化の前に入口から届いていたブロックのうち、分岐が一方に畳まれて届かなくなったものは、最適化の後に捨てます
（間接ジャンプがある関数を除きます）。初めから届かないブロック（unwind 表が導かない例外の着地点など）は残します。

## SSA（`src/ssa/`）

- `mod.rs`: IR を SSA 形式にします。レジスタの定義ごとに値（専用の範囲のレジスタ番号）を割り当て、
  合流点でまだ生きているレジスタには φ を置きます（支配辺境による）。呼び出しが暗黙に読み書きする
  レジスタは文の横に記録します。整合性の検査（定義は 1 回、読み出しは定義に支配される、φ の引数の数）と、
  元の IR への戻しも持ちます。
- 呼び出しが壊した値の読み出し: 呼び出しが書くレジスタのうち、規約が戻り値を置かないレジスタの、その呼び出しが
  残した値を（φ を経ずに）読む式は、未定義の値にします。前の値は残っておらず、そこにある値には意味がないからです。
  未定義の値はどの値でもよいので、簡約ではゼロとして扱います（マスクやシフトをしても未定義のまま、
  横に並べたビットとの論理和はそのビット）。呼び出しが壊したレジスタへの 1 バイトの書き込み（`mov cl, 1`）は、
  書いたビットだけになります。出力では `0 /* undefined */` と書き、インタプリタも呼び出しの後の
  そうしたレジスタをゼロとして読みます。
- `sccp.rs`: 条件付き定数伝播。実行されうる経路だけで値を計算し、定数で決まる分岐を無条件の分岐にします。
- `ranges.rs`: 既知ビットと値域。値ごとに、0 とわかるビット・1 とわかるビット・符号なしの範囲 [lo, hi] を持ち、
  演算（論理演算、定数でのシフト、加減乗算、除算と剰余、符号拡張、幅への切り詰め、幅を指定したロード）を通して伝え、
  φ で合わせ、ループでは数回変わった範囲を端まで広げてから不動点を求め、最後に 2 回計算し直して狭めます。
  分岐の辺でも狭めます。`x < 8` の真の辺だけが入るブロックとそれが支配するブロックでは x は [0, 7] で、
  `(x & 1) == 0` の後では最下位ビットが 0 です。辺の条件は、`x - k` やマスク、値の定義（数段まで）をさかのぼって
  元の値に移し、φ の引数にはその辺の条件を使います。定数伝播と同じく実行されうる辺だけが値を運びます。
  結果から、値がすでに収まるマスク、負にならない値の符号拡張、分岐の条件で 1 つに決まる値の読み出し、
  範囲で決まる分岐、switch の添字がとらない case と、すべての値に case があるときの default を除き、
  届かなくなったブロックを捨てます。マスクや拡張を除くのは式の幅（型の手がかり）が変わらないときだけで、
  代入と return の最上位にあるレジスタ幅のマスクと、部分書き込みが残すビットの形はそのまま残します。
  比較や符号付き演算の下では、定数伝播と同じく幅を変える置き換えをしません。最適化の最後と、変数の分割の後の
  2 回走ります。同じ伝達関数は、レジスタについて何も知らないときの式の値域としても使い、`simplify` のマスクの整理と
  除算の認識、ジャンプテーブルの添字の上限、出力のマスクの省略（`render/expr.rs` の `fits`）がこれを使います。
- 可変長引数の呼び出し（printf など）: 書式文字列の番地を定数伝播で求め、書式から引数の数を数えます。
  レジスタに収まらない分は、呼び出しの時点のスタックから読む引数として並べます。最適化の前に数えるので、
  呼び出しの直前の `push` などによるスタックポインタの変化がまだ IR に残っています。
- 可変長引数の関数（`analysis/variadic.rs`）: SysV と AArch64 の可変長引数の関数は、入口で名前のある引数より後ろの
  整数の引数レジスタを最後のものまで 8 バイトおきに、浮動小数点の引数レジスタ 8 つを両半分とも 16 バイトおきに
  フレームへ保存します（SysV は al が 0 でないときだけ浮動小数点のほうを保存します）。この保存があり、保存した
  整数レジスタをほかのどこも読まないとき、そのレジスタを引数から除いて宣言を `(int32_t a0, ...)` とし、
  出力ではこの保存と SysV の al の判定を書きません（IR には残すので、`va_arg` の展開が保存した値を読むのは変わりません）。
  最初の引数レジスタから保存するものは、最適化なしのコードが引数をすべて退避するのと区別がつかないので、可変長引数の関数とは見なしません。
- 変数の分割: φ でつながる値の集まりを 1 つの変数とみなし、汎用レジスタとベクトルレジスタの各半分を、
  それが保持する変数 `v1`, `v2`, … に分けます。スタックポインタと、フレームを指すのに使われている
  フレームポインタは分けません。引数の入口の値は引数の名前のまま残します。
  呼び出しが 2 つ目以降の戻り値を置くレジスタ（rdx や Go の後続の戻り値）も、呼び出しの直後に変数へ移し、
  出力では `/* also returned by the call */` と注記します。番号は定義が現れる順で、実行ごとに変わりません。
  そのレジスタが引数のレジスタでもあるとき（Go の rbx や SysV の rdx）、出力ではレジスタ名が引数の名前で読まれるので、
  コピーの伝播はこの変数を読む側へ畳み込まず、別の変数へ移すときだけ畳み込みます。コピーの行はレジスタ名のまま書きます。
  呼び出しの結果を別の変数へ移すだけのコピーは、後続の戻り値のコピーをはさんでいても、その変数へ直接受けます。
  浮動小数点引数のわからない呼び出し（間接呼び出しや、プロトタイプのない import）は xmm0〜xmm7 の下位半分を
  読むものとして、そこに届く値はレジスタに残します。ただし、浮動小数点のスカラーではなくベクトルのデータと
  わかる値は分けます。隣り合う 16 バイトを上下の半分に読み込んだ値（`movups` によるコピー）、
  整数のレーン演算が読むか結果とする値、整数の加減乗算の値、それらから浮動小数点演算なしに計算した値です。
  そうした呼び出しだけが読む φ は値をつながないので、ベクトルのデータと、それより前にレジスタにあった値は別の変数になります。
  呼び出しが引数のほかに読みうるレジスタ（AArch64 の x8、SysV の al）の値も、ほかの文が式として読むなら
  計算の途中の値として変数に分けます（`x8 = a0 % 3; v2 = table[x8];` の x8 など）。
  変数の分割の前に、AArch64 の x8 に置いた値のうち、レジスタが変わるまでにどの経路でも読まれないものを除きます。
  呼び出しは、要約が結果をメモリへ返さないと示す呼び出し先なら x8 を読まないものとして、ブロックをまたいで調べます
  （switch の前に計算したジャンプ表の飛び先が、各 case の呼び出しで読まれるものとして残らないように）。
  使われない値のうち、コードや定数のデータ、関数自身のフレームからしか読まないもの（フレームに退避した添字で読む
  ジャンプ表の要素など）も除きます。
  呼び出しの戻り値を受けた変数が、直後に別の変数へ移されるだけなら、戻り値を直接その変数に入れます。
- Go の複数の戻り値: 呼び出しの直後に呼び出し元が読む結果レジスタから、関数が返す値の数を決め、`return v1; /* also returns v2 */`
  と出します（`return` は `results(rax, rbx, ...)` を返す形で持つので、2 つ目以降の計算も残ります）。
- 戻り値: 呼び出し元の誰も戻り値を読まない関数に加え、ある経路で戻り値レジスタを設定しないまま戻る関数も `void` とします（そのレジスタで引数を渡さない規約に限ります）。
- Go（x86-64）: xmm15 は常に 0 として扱います（関数の入口でも呼び出しの後でも 0 のまま）。書き込みバリア
  `runtime.gcWriteBarrierN` は、引数を取らず r11 だけを書き換えて記録先を r11 に返す呼び出しとして扱います。
  呼び出しの直後に xmm15 を 0 にし直す呼び出し先は、アセンブリの ABI（引数も戻り値もスタックで渡す）の関数として、
  スタックの引数を読んで解析し、呼び出し側もスタックのスロットを引数として出します。呼び出し先が読む最後の引数より
  後ろに書く値（または番地を別の呼び出しに渡すスロット）を戻り値とし、引数はその手前までとします。呼び出し先が
  引数のスロットの下位のバイトだけを読むなら、呼び出し側もその幅だけを読む引数にします。呼び出し先は戻るときに
  そのスロットの値を `return` で返します。呼び出し側では、Go のレジスタの ABI が戻り値を返すレジスタ（rax, rbx, …）
  の値を、呼び出しの直後に呼び出し先がスロットへ書いたものとして持ち上げます。同じブロックでそのスロットを丸ごと
  読む命令はそのレジスタを読むようにし、ほかに読みうる経路がなければスロットへの書き込みは置きません。こうして
  `v = f(a, b)` の形で出ます。スタックポインタを別のレジスタに保存してから別のスタックへ移る関数も追えるように、
  この ABI の関数では、どのレジスタについてもスタックポインタからの位置を追います。
  Go には例外で入るランディングパッドがないので、どの経路も届かないブロック（戻らない呼び出しの後の
  エピローグなど）は捨てます。`runtime.mcall` は、コード上は戻りませんが呼び出し側から見ると戻る関数として扱います。
- 部分書き込みの縮小: 部分書き込みで残したビットを、どの読み出しも見ないなら書き込んだ値だけにします
  （使われるビットを、使う側から定義へ不動点まで伝えて求めます）。
- `dom.rs`: 支配木と支配辺境。

## analysis と typing（`src/analysis/`）

- `summary.rs`: 関数の要約（読む整数引数と浮動小数点引数の数、戻らないか、32 ビットの値だけを返すか）。浮動小数点引数の数がわかる呼び出しは、それを整数引数の後に並べて名前で渡し、他のベクトルレジスタは読まないものとします。必要になったときに、呼び出しグラフを強連結成分に分け、
  呼び出し先の成分から順に、成分の中で不動点まで求めてキャッシュします。lifter はこれを使って呼び出しに
  引数を持たせ、戻らない関数の呼び出しでブロックを終えます。
  32 ビットの値だけを返すかは、成分の中では返すと仮定して始め、返さないとわかった関数から順に打ち消します。
  返すレジスタへの書き込みがすべて 32 ビット（ゼロ拡張のマスク、またはそうした関数の呼び出しの結果。32 ビットに
  収まる定数はどちらでもよい）なら 32 ビットを返すとします。`widths` は、そうした関数の呼び出しの結果を
  32 ビットの書き込みとして数えます。不動点に達する前に打ち切った成分では仮定を取り消します。
  求める処理は並列に進めます。まず呼び出しグラフを、前の段で見つけた関数をまとめて並列に持ち上げながら広げ、
  そのあと強連結成分に分けます。各成分は、呼び出す成分がすべて決まった時点で空いているスレッドが求めます。
  成分の中では、前の段で変わった関数の呼び出し元を、前の段の終わりの要約から段ごとにまとめて並列に求め直します
  （呼び出し元が読むのは持ち上げに要る部分と 32 ビットの値だけを返すかなので、そこが変わったときだけ求め直します）。
  持ち上げた結果が前の段と同じなら、そこから求めたシグネチャも使い回します。各成分の結果は呼び出し先の成分の
  最終的な要約だけで決まり、段の中で求める順番にもよらないので、問い合わせの順番やスレッドの数によらず同じ結果になります。
  壊すレジスタ（`clobbers.rs`）: 本体のブロックをたどり、各レジスタが入口の値か、入口のスタックポインタからの
  位置か、それ以外かを、フレームのスロット（8 バイトごと）の中身とともに追います。どの return でも入口の値に
  戻っていないレジスタを、その関数が壊すレジスタとします。入口で保存して戻る前に読み戻すレジスタ
  （push と pop、stp と ldp）は壊しません。呼び出しはその呼び出し先が壊すレジスタを書き、呼び出し先の
  フレーム（スタックポインタより下）のスロットを忘れます。レジスタを通るジャンプ、関数の外への分岐、
  スタックポインタが元に戻らない return があれば、壊すレジスタはわからないものとします。Go のスタックの
  伸長の経路は除き、規約が保つと決めているレジスタ（スタックポインタ、Go の r14 と xmm15）は数えません。
  成分の中では、他の項目とは別に、何も壊さないと仮定して始め、増えなくなるまで段ごとに並列に求めます。
  各関数は一度だけ持ち上げ（成分の中の呼び出しは、名前が戻らないと言わない限り戻り、引数を渡さないとします。
  他の項目を求める最初の段と同じ持ち上げなので共有されます）、段ごとに成分の中の呼び出し先の壊すレジスタを
  引き直します。他の項目を求める間は、成分の中の呼び出しは規約の分を壊すとし、最後に結果を入れます。
  成分の中の関数の引数の数も、0 から始めます（引数の数のわからない呼び出しはすべての引数レジスタを読み、
  そこに届く値が呼び出し元の引数として残るためです）。関数の途中への呼び出し（Go のブロックを
  ゼロにするコードやコピーするコードへの呼び出し）は、そこから先のコードの壊すレジスタを使います。
  lifter は呼び出しにこれを持たせ、呼び出しが書くレジスタ（データフロー・SSA・インタプリタ）は規約の代わりに
  これになります。規約が壊すとするレジスタでも、呼び出し先が壊さなければ呼び出しの後も値が残り、規約が保つと
  するレジスタでも、呼び出し先が壊せば呼び出しで変わります。要約のない呼び出し（間接呼び出し、取り込んだ関数）は
  規約のままです。引数の推定だけは、規約に沿ったコードは呼び出しの後に規約が壊すとするレジスタから引数を
  取らないので、規約の壊すレジスタも書いたものとします。

- `signature.rs`: 呼び出し規約に沿って、読む前に書かれない引数レジスタから引数を推定します。
  各レジスタとスタックスロットがどの引数を持つかを経路ごとのデータフローで追い、そこを通るアクセスから
  ポインタ引数と指す先の型を決めます。整数の引数レジスタをすべて使う関数では、呼び出し元のフレームからの
  読み込み（スタックポインタか、それから作ったフレームポインタを通る）を、レジスタに続く引数とします。
  関数の要約はその数を持ち、呼び出しはその分のスタックの値を引数として読みます。
- Go の関数が先頭で行うスタックの伸長の検査（スタックポインタを goroutine の上限と比べ、足りなければ
  ランタイムに伸ばさせて関数をやり直す）は、関数のすることではないので、持ち上げた直後に取り除きます。
- 戻り値が呼び出した関数の結果だけの関数は、その関数の解析が決めた幅で返します。
- スタック保護（入口でフレームに写すガード値と、return の前にそれを比べて `__stack_chk_fail` を呼ぶ検査）は、
  関数のすることではないので、解析の最後に取り除きます。
- `results.rs`: 呼び出し元が戻り値を読むか。戻り値のレジスタには `void` の関数でも値が残るので、
  関数の本体だけでは区別できません。直接の呼び出しをバイト列から索引にして呼び出し元を見つけ、
  呼び出しの後で書く前に読む経路があれば読むとします。呼び出し元の return に渡るだけなら、
  呼び出し元が値を返すときに限って読むとします。デバッグ情報がなく、呼び出し元があってどれも読まず、
  定数を返す経路もない関数は `void` にします。
- `indirect.rs`: バイナリが呼び出し先を決めている間接呼び出しを、直接の呼び出しにします。持ち上げたブロックを前から
  たどり、各レジスタと関数が書いたメモリの各ワードについて、定数か、どこから来たかで名付けた不明な値とその差を追います。
  呼び出す番地が読み取り専用のデータ（関数ポインタの表、Rust のトレイトオブジェクトの表、Go の関数値など）から
  読んだ既知の関数になれば、その関数の直接の呼び出しにして要約から引数を付け、`/* via pointer at 0x55ac8 */` と
  元の表を注記します。オブジェクトの先頭にある表（C++ の仮想関数表）が同じ関数の中で決まれば `/* via vtable slot 2 */`、
  決まらなければ間接呼び出しのまま、その位置に関数を持つ表の候補を `/* vtable slot 2: f, g */` と注記します。
- `jump_table.rs`: 間接分岐の番地計算と範囲判定からジャンプテーブルを復元します。
  範囲判定のないテーブル（列挙型の判別値による分岐など）は、添字の計算から求めた上限（`ssa/ranges.rs` の値域）から、
  なければ飛び先が関数の中を指す間、コードが計算する別のアドレス（次のテーブルの先頭）に達するまで読みます。どの値も他に来ない switch は
  `default: __builtin_unreachable();` で終えます。
  前のブロックでレジスタに置いたテーブルの番地は、ブロック入口で成り立つ定数のデータフローで求め、
  見つかったテーブルの分岐先もたどって、新しいテーブルが見つからなくなるまで繰り返します。添字が定数なら
  直接の分岐にします。
- `prototypes.rs`: C の標準ライブラリ・POSIX・C++ の実行時ライブラリと、Go・Rust の実行時の関数のうち型の決まった
  ものについて、引数と戻り値の型を C の宣言の形で持ちます（規格の宣言から書いたもので、関数へのポインタは
  `void (*)(...)`、配列の引数はポインタとして書き、typedef は Linux の x86-64・AArch64 と macOS の arm64 で幅と符号が
  同じものだけ使います）。`FILE *` のような型は指す先を持たないポインタとし、`timespec`・`iovec` などどの環境でも
  並びが同じ構造体はメンバーの名前も持ちます。書式文字列を取る関数は、変換指定から可変長引数の型も決めます。
- `typing.rs`: 幅・符号・void の戻り値・部分的な戻り値・DWARF の型を決めます。プロトタイプのある関数の呼び出しでは、
  渡す値と受け取る値にその型を与え（`const char *v13`、`size_t`、`double` など）、関数の引数をそのまま渡すなら
  その引数の型にします。本体の使い方がより詳しいとき（ポインタが読む要素の型など）はそちらを残します。
  部分的な戻り値: どの戻りでも、返すレジスタに届く定義（φ とレジスタのコピーをたどります）が
  下位 1 バイト（または 2 バイト）だけを書く部分書き込みか小さな定数なら、その幅の符号なし整数を返すとします
  （`mov r15b, 1` の後の `mov eax, r15d` など）。変数の分割の前にも決めるので、部分書き込みの縮小で
  残したビットが消え、レジスタが入口の値とつながらずに変数へ分かれます。
  符号は、符号付き／符号なしの演算（比較・除算・シフト）を根拠として数え、
  根拠のない整数は C の `int` / `long` にならって符号付きとします。
  ベクトルレジスタへの読み込みは、その値を読む演算（浮動小数点か、整数のレーンか）で要素の型を決めます。
- `structures.rs`: デバッグ情報のないポインタ引数が、動かされず、添字なしの固定オフセットだけで
  2 か所以上アクセスされ、各オフセットの幅が一致して重ならないとき、そのフィールドを持つ構造体
  （`struct <関数名>_<引数名>`）を作り、引数の型にします。
  引数から計算するすべてのアドレス（引数そのもの、引数だけを保存したスタックスロット、引数から作ったレジスタを通るもの）が
  「添字 × 一定の倍数 + 定数」の形なら、構造体の配列とみなします。倍数の最大公約数を要素の大きさとし、定数を大きさで
  割った余りをフィールドにします。添字がなくループのポインタが進むだけのときは進む量を大きさとし、フィールドの並びが
  その中で繰り返すなら（1 回に複数の要素を扱うループ）、繰り返しの間隔を大きさにします。フィールドが C の並べ方
  （各フィールドが自分の幅に揃い、大きさが最大の幅の倍数）と一致するときだけ採り、定義は末尾まで埋めてその大きさにするので、
  添字の計算を C として読んでも値は変わりません。添字を別のレジスタに掛けておくコード（`v = i << 4` の後の `p + v + 8`）は、
  そのレジスタの値がアドレスの位置でも同じと分かるときに限ってアドレスへ戻し、読まれなくなったレジスタを消します
  （構造体の配列と認められたときだけ書き換えを残します）。オフセットを足すだけに使う 8 バイトの整数の引数もポインタとします。
  要素の先頭を指すレジスタは、その構造体へのポインタになります。

## render（`src/render/`）

  引数でない変数（呼び出しの戻り値や、別の構造体から読んだポインタ）も、固定オフセットだけで読み書きされるなら
  構造体へのポインタとし、`v->field_0x8` と書きます。定数を足して進む変数は配列を走査するものとして除き、
  同じ関数でフィールドの並びが同じ変数は 1 つの構造体を共有します。
- `structure/dominance.rs`: 支配木による構造化。各ブロックを、それを支配するブロックの中に 1 回だけ出します。
  1 本の前方の辺だけが入るブロックは分岐の位置に、複数の前方の辺が合流するブロックは分岐元のコードの後ろに置きます。
  支配するヘッダへの後退辺がループを作り、ループの外へ出る先はループの直後に置きます。各分岐は素通り・`break`・
  `continue` のどれかになり、どれにも当てはまらないときだけ goto になります。コンパイラが共有にした短い `return` は
  分岐の位置に複製します。最後に `for (;;)` を `while` / `do while` の形にします。
  入口から届かないコード（例外の着地点や、解析が追えなかったジャンプの先）は、それぞれを別の根とする木にして、
  関数自身のコードの後ろにラベル付きで置きます。
- `structure/duplicate.rs`: 複数の分岐が入る短いブロック（代入・ストア・呼び出しだけで先へ進む）を、各分岐に複製した版を作ります。`else` の中が `if` だけなら `else if` と続けて書きます。少しの文の後に return するラベルへの goto は、複製が数文で済むならその文と return に置き換えます。代入した値をすぐ返す 2 文は、値を返す 1 文にします。コンパイラが反転させた数え上げのループ（`n < 1` で抜ける判定の後の `i = 0; do { ...; i++; } while (i != n);`）は、
`for (i = 0; i < n; i++)` に戻します（外側の判定が内側のループにも効きます）。末尾が `if (c) break;` のループは `do-while` にします。
出口の多いループでは、1 つの分岐からしか入らない出口のコードを、ループを出る位置（`break` の前）に置いた版も試し、
残りの出口がループの後に続くようにします。複数の分岐の末尾にコンパイラが複製した同じ判定（同じ 2 か所のどちらかへ行く）を、合流点の 1 つの判定にまとめた版も試します。
  構造化の結果のラベルが減るとき、同じなら goto が減るときだけ、その版を使います。
  コンパイラがある判定の結果を知っている分岐を、その判定の先へ直接飛ばしたもの（ループの出口が後の `if (i != n)` を
  飛び越すなど）は、その判定をもう一度通るように戻した版も試します。
- `structure/short_circuit.rs`: 別の判定を補うだけの判定（1 つの判定からだけ入り、片側がその判定と同じ所へ行くもの）を、
  その判定と組んで `&&` / `||` の 1 つの条件にした版を作ります（1 つの条件に 4 つまで）。C の演算子と同じく、
  2 つ目の判定は必要なときだけ評価します。
- 構造化の後始末（`structure/cleanup.rs`）: `break` のない `for (;;)` の後ろは届かないので除きます。
  `for (;;) { if (c) { s } r }` で `s` が `r` へ流れず `r` が関数を出るものは `while (c) { s } r` に、
  本体の末尾が `if (c) continue; t` で `t` が関数を出るものは、その前に `continue` がなければ
  `do { ... } while (c); t` にします。ループ本体の末尾の `if (c) continue; t` は、本体の終わりに流れるのが
  `continue` と同じなので `if (!c) { t }` と書きます。return へ数文で着く末尾の複製は、増える行が 8 行までにします
  （`return f(x);` のように 1 行で書ける末尾は、goto と同じ長さなので、どこへでも複製します）。
- switch の前の判定の取り込み（`structure/cleanup.rs`）: `v = x - k; if (v > n) t else switch (x) { ... }` で、`k` から
  `k + n` までのすべての値に case があるものは、`t` を default にした switch にします（case のない値は switch を
  抜けるだけなので、取り込めるのはすべてを覆うときだけです）。switch の直前（または `else` の中が switch だけ）の
  `if (x == c) t` は、`t` が抜けるなら `case c:` にします。どちらも、`t` が外側のループを抜ける `break` を持つときは
  取り込みません（switch の中では switch を抜ける意味になるため）。
- `structure/classify.rs`（テスト用）: 残った goto を、それを生んだ制御フローの形（別の判定を補う判定、判定を飛び越す
  分岐、下で判定するように回したループ、まとめられた return と戻らない呼び出し、出口の多いループ、switch の展開と
  ほかの共有された末尾、既約でないループ、unwind のコードとの合流、複数のループをまとめて抜ける出口）ごとに数えます。
- `structure/build.rs`: アドレス順の構造化。支配木が深すぎて辿れない関数に使います。
- `structure/compare_chain.rs`: 1 つの値に対する比較の連鎖を switch に組み直します。レジスタの下位 32 ビットの比較
  （`w0`、`x0 & 0xffffffff`）は 32 ビットの値の比較として扱い、レジスタ全体の比較とは別の値とします。
- `structure/lower.rs`（テスト用）: 構造化したコードをブロックに戻し、インタプリタで元の IR と比べられるようにします。
- 関数の名前: デマングルした名前から引数リスト・型引数・最後の 2 つより前のモジュールのパスを除いた短い名前
  （`<core::io::error::Error>::new::<&str>` は `Error::new`）を、関数の見出しと呼び出しに使います。
  ほかの関数と同じになる名前にはアドレスを付けます。元の名前は見出しのコメントに残します。
- 文字列: 文字列を指す定数は、値として出るところで `"..."` と書きます。Go や Rust のように（ポインタ, 長さ）で渡す文字列は、
  呼び出しの引数の並びから長さを読み、終端の 0 がなくても文字列と見なします。
- `params.rs`: 呼び出しをまたいで別のレジスタやスタックのスロットへ退避し、戻してから渡す引数は、出力では引数のまま読みます（退避先が引数の値しか持たないときに限ります）。
  最適化なしのコードのように引数をスロットへ保存するだけで戻さない場合も、そのスロットの読み出しを引数として読みます。
  32 ビットの引数は 32 ビットの保存と読み出しも数え、保存より狭い読み出しは引数の下位のバイトとして読みます。保存より広い読み出し（保存しなかったバイトを読むもの）があるスロットと、ほかのオフセットからそのバイトを読み書きするスロットは、保存ごと残します。
  同じブロックで前の呼び出しが変えたレジスタからのコピーは、引数の値とは見なしません。引数のレジスタへスロットから戻すだけの関数でも、その戻しを除きます。
- `calls.rs`: 呼び出しの結果を受けた変数を、直後の文だけが 1 回読むとき、呼び出しをその文に書き込みます
  （`v3 = f(a0); g(v3, 0x1);` は `g(f(a0), 0x1);`）。読む文が結果をそのまま引数・ストアする値・代入する値・
  返す値・等価比較の片側として使い、変数の宣言の幅が呼び出しの結果の幅と同じ整数のときに限ります（狭い宣言が
  結果を切り詰めていることを失わないため）。C は引数などの評価順を決めないので、読む文のほかの部分がメモリを
  読むときは書き込みません。文は字下げを除いて 100 文字まで、条件に入れる呼び出しは 60 文字までにします。
- 構造体の定義は、1 行で 100 文字に収まるなら `struct f_a0 { int32_t field_0x0; int32_t field_0x4; };` と 1 行で書き、
  それより長いものはメンバーを 1 行ずつ書きます。
- 呼び出しの直後の trap（戻らない関数の呼び出しの後にコンパイラが置く `ud2` や `brk`）は、呼び出しが経路を終えるので印字しません。
  呼び出しの後でない trap は `__builtin_trap();` と書きます。
- `expr.rs` / `naming.rs` / `locals.rs`: 式の印字、引数・ローカル・グローバル・データシンボルの名前、
  構造体フィールドのアクセス。IR のアドレス計算はバイト単位なので、型付きポインタへの加算は
  要素の大きさで割り切れるときに要素単位（`p[i]`、`p + 1`）で書き、割り切れないときは
  `(uint8_t *)p + n` とバイト単位に直して、C として読んでも同じ値になるようにします。
  構造体の配列へのポインタでは、要素の大きさで割った商を添字に、余りをフィールドにして
  `p[i].field_0x8`（添字が 0 なら `p->field_0x8`）と書き、フィールドの番地を値として使うところは
  `&p[i].field_0x8` と書きます。和の内側に要素単位で書ける部分があっても全体が割り切れないときは、
  内側も含めてバイト単位に直します（内側だけを要素単位にすると C が掛け算してしまうため）。
  スタックのローカルが構造体へのポインタを持つときも、要素の大きさが分からなければ同じくバイト単位に直します。
- `int.rs`: 整数の式を C として読んだときの値。IR は 64 ビットの値で計算しますが、C は被演算子の型
  （整数拡張の後で `int` 以上）の幅で計算し、狭い値はその型の符号に従って広げます。印字した式ごとに、
  その型と、IR の値と下位何ビットまで一致するか（両方を際限なく広げたとき。全ビットなら「等しい」）を持ち、
  読む側が必要とするビット数と比べて、キャストや演算の拡張を決めます。読む側の必要なビット数は、代入なら
  宣言した型の幅、ストアならその幅、`return` なら戻り値の型の幅、論理右シフトの被演算子ならシフト量だけ多い
  ビット数、符号なし除算の被演算子なら全ビットです。規則は少数です。
  - 足りない値は、その値が収まる符号なしの型（符号拡張した値なら符号付きの型）へのキャストで正します
    （符号付きで宣言した `w0` の論理右シフトは `(uint32_t)a0 >> 0x1f`、`popcount64(w0)` は
    `__builtin_popcountll((uint32_t)a0)`、`sext32(x0) - w1` は `(int64_t)a0 - (uint32_t)a1`）。
  - C の計算の幅が読む側の必要とするビット数より狭い演算は、被演算子の一方を 64 ビットの型にして広げます
    （32 ビットどうしの積を右シフトするなら `(uint64_t)v1 * ... >> 0x1`、シフトする定数は `0x1ULL << n`）。
    IR の値に等しく、C の型であふれない小さな値どうしの演算は広げません。
  - 下位ビットのマスクは、値がすでにその幅に収まるか、読む側がその幅しか見ないときだけ省きます
    （桁上がりしうる 32 ビットの和のマスクは残ります）。
  - 符号付きの演算（算術右シフト、符号付き除算）は、その幅の符号付きの型でない被演算子をその型にします。
    符号拡張（`sext`）は、値がすでにその幅の符号付きの型なら何も書きません。C が広げるときに符号拡張するためです。

  比較も同じ考えで、IR の比較は両辺の広い方の幅で行います。C が両辺を変換する型が IR の比較の幅以下で
  符号が比較と合うか、C の比べる値が IR の値をその幅で読んだもの（符号なしならゼロ拡張、符号付きなら符号拡張）に
  等しいとわかる辺はそのまま書き、そうでない辺はその幅と符号の型にします
  （`(v & 0xff) < 0` ではなく `(int8_t)v < 0`、`*(int32_t *)(p + 0x8) > 0`、64 ビットの変数の下位 32 ビットとの比較は
  `(uint32_t)v == 0x5`）。符号なしの比較で、両辺を揃えた C の型が符号付きのまま負になりうる値を比べるときは、
  片方の辺を符号なしの型にします（`(uint64_t)v > 0x1`）。注記ではなく C の型で符号なしの比較を表します。
  各変数が代入される値の収まるビット数を代入から求めておき（式の既知ビットと値域
  `ssa/ranges.rs` の `expression` も使い、1 ラウンドに 1 ビットずつ育つカウンタは次の整数型の幅まで一度に広げます）、
  収まる値のマスクは省きます。値が宣言の幅に収まる変数（符号付きなら符号ビットより下に収まる変数）は、
  読むときも IR の値に等しいとみなします。
  switch の添字も等価の比較として読みます。
  引数でない汎用レジスタ（スタックポインタを除く）を本体が使うときは、64 ビットの名前で `uint64_t` の変数として
  宣言します（代入されるまでは関数に入ったときの値です）。値として使う関数のアドレスは、関数の前で
  型のわからない関数（`void f(void);`）として宣言し、整数として読むところでは `(uintptr_t)f` と書きます。
- `variables.rs`: 変数と一時変数の型を使われ方から決め、関数の先頭で宣言します。浮動小数点演算が
  計算する・読む値は `double` / `float`（コピーを通して伝える）、加算以外の演算に使われずアドレスに
  なる値はポインタ（指す先は、元の引数の型か、アクセスの幅と浮動小数点としての使われ方から）、
  それ以外は整数で、幅は `widths.rs`、符号は符号付き／符号なしの演算のうち多く読む方から決めます
  （同数か根拠がなければ符号付き）。
- `widths.rs`: 整数の変数の幅。印字が各式に求めるビット数（`int.rs` の規則と同じ。代入はその変数の宣言の幅、
  ストアはその幅、比較は両辺の広い方の幅、マスクはその幅、論理右シフトはシフト量だけ多く、ポインタや
  フレームの番地との和は全ビット）を後ろ向きにたどり、どの読み手も下位 8・16・32 ビットしか見ない変数は
  その幅で宣言します。読み手がそれより先を見ても、代入される値がすべて 32 ビットに収まる変数は
  符号なし 32 ビットで宣言します（`uint32_t` なら広げても IR の値に等しいため）。代入の求める幅は代入先の
  宣言で変わるので、すべて狭いとして始め、広げる必要のある変数を広げて、変わらなくなるまで繰り返します。
  狭い変数は、32 ビットに切り詰めた値の代入や狭い読み出しのマスク・キャストを省ける一方、64 ビットとして
  読まれる和・積・左シフト・符号反転などでは C が狭い幅で計算するのでキャストが要ります。後者が前者以上なら
  64 ビットのままにします。符号は、読み手が自分でゼロ拡張する（`v & 0xffffffff` を広く読む）変数と、
  8・16 ビットの変数では、符号付きの演算が読まない限り符号なしにします
  （`v2 = ((v5 + 0x1) & 0xffffffff);` ではなく `int32_t v2; v2 = v5 + 0x1;`）。
- `locals.rs`: スタックスロットを `local_N` と名付け、型を決めます。入れる値・取り出す先の変数や引数の型が
  浮動小数点かポインタならその型、浮動小数点演算が読むなら `double` / `float`、アドレスの土台になるなら
  ポインタ（指す先はアクセスの幅と使われ方から）です。符号は符号付き／符号なしの演算（被演算子の中で
  読まれるものも含む）と符号拡張から決めます。根拠がなければ、32 ビット以下のスロットは符号拡張する読み出しが
  あるときだけ符号付き（ゼロ拡張して読むスロットを符号なしにすると、広く読んでもキャストが要らないため）、
  64 ビットのスロットは符号付きとします。ポインタのローカルを通るアクセスも要素単位（`local_0[i]`）で書きます。

## 外側の層

- `service.rs`: バイナリを開き、関数ごとの解析をキャッシュします。CLI・スクリプト API・MCP が共有します。
- `card.rs`: 関数の要約（指定したトークン数に収まる JSON）。
- `sigs.rs`: 関数の形を正規化したハッシュによるシグネチャ DB。
- `script/` と `mcp.rs`: 内蔵の JavaScript エンジンで動くスクリプト API と、それを公開する MCP サーバ。

## 検証の仕組み

正しさを、出力の見た目ではなく意味で確かめることを重視しています。

- 実機との比較（`src/lift/hardware/`）: レジスタとフラグだけを読み書きする命令をランダムに生成し、
  ランダムなレジスタの値から、実機での実行結果と lift した IR の実行結果を比べます。レジスタに加え、
  条件それぞれの成否も比べます。プロセッサが定義しない符号化と、CPU が未定義とするフラグを読む条件は除きます。
  AArch64 は arm64 の macOS 上で直接、x86-64 は小さな実行プログラム（`x86_64.c`）をテスト時にビルドして動かします
  （x86-64 の Linux では直接、arm64 の macOS ではシステムの変換機能で）。浮動小数点レジスタ（v0〜v7、xmm0〜xmm7、
  ymm0〜ymm7 の上位半分）と
  スカラーの浮動小数点命令も含み、初期値には ±0、±∞、NaN、非正規化数を混ぜます。NaN のビット列は ISA が決めるので、
  インタプリタは x86 の規則（最初の NaN を quiet にする、なければ不定値）を再現します。
  ロードとストアも照合します。作業領域の中を指すポインタ用レジスタをベースにしたアドレス指定（AArch64 は前置・後置
  インデックス、拡張・シフト付きのレジスタオフセット、ペア。x86-64 はメモリオペランドを取る整数・SSE 命令の SIB 形式）を
  生成し、レジスタと領域の内容を比べます。x86-64 の実行器は領域を固定アドレスに置きます。
  フラグの変換は、ISA ごとのフラグの定義から条件を直接計算する単体テスト（`flags.rs`）でも、全環境で確かめます。
- 動作の比較（`semantics_tests.rs`）: テスト用の全バイナリの全関数で、最適化前後の IR をランダムな入力で実行し、戻り値・呼び出し・メモリを比べます。
  構造化したコードもブロックに戻して同じように実行し、最適化後の IR と比べます。SSA への変換と戻しが関数を変えないことも確かめます。
- 再コンパイル（`tests/recompile.rs`）: 最適化後の IR が整数レジスタの計算だけでできている関数（メモリ、呼び出し、
  グローバルを使わず、整数の引数と戻り値を持つ）について、疑似 C を C コンパイラ（システムの clang、`-O1` と `-O0`）で
  コンパイルし、動作の比較と同じ入力で実行して、インタプリタの戻り値と戻り値の幅で比べます。引数は宣言した型の値に
  変換してから両方に渡します。インタプリタが値を決められない実行と、引数でないレジスタを読む実行、ほかの関数の
アドレスを使う関数の実行（アドレスはバイナリとコンパイルしたプログラムで違います）は、理由を数えて除きます。
アドレスを使う関数は、宣言された関数の空の定義を加えてコンパイルとリンクだけを確かめます。
  コンパイルできない関数も、最初のエラーとともに記録します。clang がなければテストを飛ばします。
- 不変条件（`tests/invariants.rs`）: 飛び先のない goto、代入されないレジスタの読み取り、疑似 C で落ちた文がないことを確かめます。
- 正解率（`tests/metrics.rs`）: デバッグ情報を正解として、関数の発見と引数・戻り値の推定の正解率を測ります。
- 読みやすさ（`tests/golden.rs`）: テスト用バイナリごとに、全関数の疑似 C の行数、宣言した変数、キャスト、残ったレジスタ名、
  `/* unsigned */` の注記（今は出しません）、`__builtin_trap`、goto の数を数えて `tests/golden/readability.txt` に記録します。
- 難易度別の期待値（`tests/ladder.sh`）: 種別が `known_*` の行は、まだ満たせていない目標です。

いずれも今の値を `tests/golden/` に記録し、悪化すればテストが失敗します。
