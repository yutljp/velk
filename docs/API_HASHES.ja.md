# API ハッシュ

名前のテーブルを走査し、名前のハッシュを定数と比較して関数のアドレスを
返すコードがあります。velk は IR の呼び出し結果と比較のオペランドをたどり、
復元したハッシュ関数を Windows と C ライブラリのエクスポート名の小さな
一覧に対して実行します。命令のバイト列や組み込みのハッシュ式では識別しません。

結果は CLI の `--summary`、JavaScript の `f.summary()`、MCP の
`velk_run_script`、および `--serve` に送るスクリプトが返す関数の要約の
`apiHashes` に含まれます。各項目には、呼び出しの `block` と `statement`、
アドレスを返す `resolver` とハッシュ関数 `routine` のアドレス、定数 `hash`、
一致した名前の一覧 `candidates`、`complete` を含みます。文の番号は最適化された
IR のもので、命令アドレスではありません。`routine` は個別のハッシュ関数、
または検索全体をエミュレートする場合は resolver 自身です。候補が空なら一致は
なく、複数なら衝突です。`complete: false` は他の一致候補が省略されているか、
評価の上限に達した可能性を示します。検索全体のエミュレーションでは resolver が
返した名前を報告し、衝突候補をすべて列挙しません。`indirectCall` は間接呼び出しか、
検索結果をそのまま返す i386 の関数かを示します。

一致した名前は C のコメントにも表示します。間接呼び出しの動作は変更しません。
一致だけでは読み込まれたモジュール、転送エクスポート、実際のテーブルに名前が
あるかを判断できません。ハッシュから直接呼び出しや型宣言を作りません。

解析には、定数引数を持つ resolver の直接呼び出しと、返されたアドレスによる
間接呼び出しが必要です。i386 では検索結果をそのまま返す関数にも対応します。
個別のハッシュ関数は、同梱のエクスポート名一覧に対して評価します。終端ゼロの
バイト文字列、呼び出し時に定数となる整数引数、関数が 16 ビット文字を読む場合の
UTF-16 文字列に対応します。

ハッシュ計算がインライン化されている場合、検索全体をエミュレートし、返された
アドレスに対応する名前を読み取れます。ELF の動的シンボルテーブルを走査する
resolver も対象です。32 ビットと 64 ビットの Windows バイナリーでは、エミュレーターが
合成 PEB ローダーリストとモジュールのエクスポートテーブルを用意します。resolver は
それらを走査して名前付きエクスポートを返せます。エミュレーションはバイナリーと
合成プロセス状態を使い、実行中のプロセスは調べません。実プロセスでどのモジュールが
読み込まれているかは判断しません。スタック引数は呼び出し時に定数なら復元します。
ELF の対象命令セットは x86-64、i386、AArch64 です。Windows resolver のエミュレーションは
x86-64 と i386 に対応します。Go のバイナリーは対象外です。i386 の間接呼び出しで
引数の数が不明な場合は逆コンパイルに失敗します。i386 のテスト用ソースでは検索結果を返します。

一回の探索は IR 文と名前の評価を合わせて 2,000,000 回を上限とします。検索全体の
エミュレーションは 200,000 IR ステップ、100 ミリ秒以内で、呼び出し元の期限にも
従います。個別のハッシュ関数による各名前の評価は IR の 10,000 文を上限とします。
ホストの API やシステムコールは実行しません。個別のハッシュ関数で使う名前一覧は
`src/api_hashes/exports.txt` にあります。

次の例を実行する前に、ソースからテスト用バイナリーを作成します。

```sh
sh tests/make_api_hash_fixtures.sh
velk --summary target/api-hash-fixtures/x86_64.O2.elf case_ror13
velk -D target/api-hash-fixtures/x86_64.O2.elf case_ror13
```

```js
const b = velk.open("target/api-hash-fixtures/x86_64.O2.elf");
b.getFunction("case_ror13").summary().apiHashes;
```

MCP ではこの JavaScript を `velk_run_script` の `code` に渡します。
同じ JSON 配列をテキストで返します。テスト用ソースには ROR13、djb2、
FNV-1a、シード付き FNV-1a、UTF-16 FNV-1a、CRC32、独自のハッシュ、衝突、未知のハッシュ、
PE エクスポートディレクトリー、PEB を走査する resolver、インライン化されたハッシュ、
ELF 動的シンボルを含めます。x86-64、i386、AArch64 向けの位置独立コードとしてコンパイルします。
