# API ハッシュ

名前のテーブルを走査し、名前のハッシュを定数と比較して関数のアドレスを
返すコードがあります。velk は IR の呼び出し結果と比較のオペランドをたどり、
復元したハッシュ関数を Windows と C ライブラリのエクスポート名の小さな
一覧に対して実行します。命令のバイト列や組み込みのハッシュ式では識別しません。

結果は CLI の `--summary`、JavaScript の `f.summary()`、MCP の
`velk_run_script` が返す関数の要約の `apiHashes` に含まれます。各項目には、
呼び出しの `block` と `statement`、アドレスを返す `resolver`、ハッシュ
関数 `routine` のアドレス、定数 `hash`、一致した名前の一覧 `candidates`、
`complete` を含みます。文の番号は最適化された IR のもので、命令アドレス
ではありません。候補が空なら一致はなく、複数なら衝突です。
`complete: false` は実行の失敗や上限により、見落としがあり得ることを示します。
`indirectCall` は間接呼び出しか、検索結果をそのまま返す i386 の関数かを示します。

一致した名前は C のコメントにも表示します。間接呼び出しの動作は変更しません。
一致だけでは読み込まれたモジュール、転送エクスポート、実際のテーブルに名前が
あるかを判断できません。ハッシュから直接呼び出しや型宣言を作りません。

現在の解析には、定数引数を持つ直接呼び出し、その引数とハッシュ関数の直接
呼び出し結果を等値比較するループ、返されたアドレスによる間接呼び出しが
必要です。i386 では検索結果をそのまま返す関数にも対応します。
ハッシュ関数の引数は終端ゼロのバイト列へのポインター一つです。
スタック領域とレジスターのコピーには既存のメモリ解析と SSA 解析を使います。
インライン化されたハッシュ、モジュール名との合成、ワイド文字列、追加引数の
初期値、異なる定義が合流した結果は認識できない場合があります。
オフセットから PEB やリンクマップの構造を確認する解析は行いません。
対象の命令セットは x86-64、i386、AArch64 です。Go のバイナリーは対象外です。
i386 の間接呼び出しで引数の数が不明な場合は、
逆コンパイルに失敗します。i386 のテスト用ソースでは検索結果を返します。

一回の探索は IR 文と名前の評価を合わせて 2,000,000 回、各名前の実行は IR の 10,000 文を
上限とし、呼び出し元の期限にも従います。ホストの API やシステムコールは
実行しません。名前の一覧は `src/api_hashes/exports.txt` にあります。

次の例を実行する前に、ソースからテスト用バイナリーを作成します。

```sh
sh tests/make_api_hash_fixtures.sh
velk --summary target/api-hash-fixtures/x86_64.O2.elf case_ror13
velk -D target/api-hash-fixtures/x86_64.O2.elf case_ror13
```

```js
const b = velk.open("target/api-hash-fixtures/x86_64.O2.elf");
b.getFunction("case_ror13").summary().apiHashes;
```

MCP ではこの JavaScript を `velk_run_script` の `code` に渡します。
同じ JSON 配列をテキストで返します。テスト用ソースには ROR13、djb2、
FNV-1a、CRC32、独自のハッシュ、衝突、未知のハッシュ、PE エクスポート
ディレクトリー、ELF 動的シンボルを含めます。x86-64、i386、AArch64 向けの
位置独立コードとしてコンパイルします。
