# 制御フローの簡略化

既定の解析では、結果を証明できた条件分岐だけを除去します。
`x * (x + odd)` と `x * (x - odd)` の最下位ビットがゼロであること、
これらの積を符号なし整数として 2 で割った余り、同じ整数同士の減算と
排他的論理和、整数とそのビット反転との論理積を扱います。規則は IR の
整数幅と桁あふれ時の折り返しに従います。メモリを読む式や例外を起こしうる式は
これらの恒等式の対象から除きます。既存の定数伝播と範囲解析も、追跡した値から
分岐条件を証明します。これには、メモリ解析が格納値を安全に転送できる、
外部から参照されないスタック領域も含まれます。

ディスパッチャの復元は、状態変数を一つだけ検査する比較の連鎖と switch を
扱います。流入する各辺の状態は、定数か、条件によって二つの定数から選ぶ値で
なければなりません。定数ごとに検査をたどり、流入辺を直接分岐に置き換えます。
検査ブロックに到達しなくなったと証明してから、それらを除去します。
不明な状態代入、解決できない辺、例外ハンドラがある場合は復元しません。
ヘッダがほかの処理も行う場合はそのまま残します。

関数カードと JavaScript の `Function.summary()` は、MCP 経由のスクリプトでも
`simplification` オブジェクトを返します。

- `simplified`: 式、条件分岐、ディスパッチャのいずれかを簡略化したか。
- `predicatesRemoved`: 結果が定数と証明された条件分岐の数。
- `dispatcherStatesRemoved`: 検査を迂回する直接分岐に置き換えた、流入する定数状態の種類数。
- `mbaExpressionsSimplified`: ビット演算と算術演算を混ぜた式の置換の数。
  [式の簡略化](MBA.ja.md)を参照してください。

`tests/cases/control_flow/` には、直線的な処理、分岐、ループについて、
平坦化した関数と元の関数を用意しています。整数の条件式と、ディスパッチャを
残す必要がある変数による遷移も含みます。
`tests/make_control_flow_fixtures.sh` は Clang を使い、x86-64 と AArch64 の
自立したオブジェクトを `-O0` と `-O2` で生成します。
制御フローの統合テストは出力した C をコンパイルし、独立した符号なし整数の式と
戻り値を比較します。単体テストでは整数の恒等式の検証だけに Z3 を使用します。
実行時の解析ではソルバを呼びません。

## 既存の Go と Rust 関数から取り除く検査

Go と Rust のフィクスチャで計算に関係する変更は、次の検査に限られます。

- x86-64 の `runtime.mapaccess2`: `v24 != 0` の内側にある `v24 == 0` の分岐には
  到達しません。検査の間に代入や呼び出しはありません。その前の呼び出しの戻り値は
  任意であり、証明はその値を制限しません。
- x86-64 の `rustc_demangle::demangle`: `0x46695` の検査に入るすべての経路では、
  符号なしの長さが 2 以上のままです。外側の検査は 2 以下の長さだけを通すため、
  長さは代入済みの定数 2 と等しくなります。したがって `0x466bf` への分岐は不可能です。
  検査の間に長さを変更する呼び出しや代入はありません。分岐の削除により、後続コードを
  表示する際の入れ子も変わります。
- AArch64 の `gimli::read::rnglists::RngListIter::next`（リトルエンディアンの
  `EndianSlice` を使用）: `v11 <= 1` かつ `v11 != 1` の下では、符号なしバイトの
  `v11` は 0 です。内側の `v11 != 0` の分岐には到達しません。検査の間に代入や
  呼び出しはありません。

`reduced_existing_checks_preserve_calls_and_memory` は、この 3 つの検査を縮小した C を
`-O0` と `-O2` でコンパイルし、未定義動作を検査して実行します。各検査につき
131,072 個の入力で結果、呼び出し回数、変更されたメモリを比較します。すべての
バイト値と符号なし 64 ビットの境界値を含みます。これは縮小した検査の実行であり、
Go ランタイムや Rust ライブラリの関数全体を実行するものではありません。

変更された関数の実体は次のとおりです。

| フィクスチャ | 関数 | アドレス |
|---|---|---|
| `go_probe`, `go_stripped` | `runtime.mapaccess2` | `0x45c120` |
| `rust_demo`, `rust_probe`, `rust_probe_stripped` | `rustc_demangle::demangle` | `0x46024` |
| `rust_demo_arm64`, `rust_probe_arm64`, `rust_probe_arm64_stripped` | `gimli::read::rnglists::RngListIter::next` | `0x100014670` |

demangler の `0x463fa` へ入るすべての経路では、長さは 2 以上です。
2 バイトの接頭辞の経路では 2 を代入し、3 バイトの接頭辞の経路では 3 以上、
4 バイトの接頭辞の経路では 4 以上を保ちます。`0x46675` へ到達する経路はすべて
この領域から来ており、長さを変更しません。そのため `0x46695` への辺にある
「2 以下」という制約と合わせると、長さは 2 に決まります。
`existing_dominating_checks_exclude_the_removed_paths` は、この 3 種類の検査条件の
組み合わせが成立しないことを、Z3 を使って 8、16、32、64 ビットで証明します。
