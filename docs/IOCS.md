# Indicator extraction

`velk --iocs FILE` lists indicators found in printable static strings and strings recovered by bounded emulation. Results are grouped by kind. Add `--json` for a JSON array with stable `kind`, `value`, `sources`, and `references` fields. Each reference contains a function and instruction or block address. Equal kind and value pairs are combined, and their source kinds and reference sites are retained.

The script API provides the same result through `binary.iocs()`, including scripts run with `--run`, `--mcp`, and `--serve`. Sources are `staticString`, `decodedString`, and `staticConstant`. No network requests or reputation lookups are made.

The classifier recognizes URLs with HTTP, HTTPS, FTP, WebSocket, and secure WebSocket schemes; domains whose final label is in a bundled conservative TLD list; IPv4 and IPv6 addresses; email addresses; Windows paths; POSIX paths; registry paths beginning with `HKLM\\` or `HKEY_`; and user agent strings beginning with `Mozilla/`. When bounded emulation recovers a string as an argument to `CreateMutex`, `OpenMutex`, `CreateEvent`, `InternetOpen`, or `WinHttpOpen`, it also records that API-specific kind. Crypto constant names come from the existing constant signature detector. A dotted numeric value is accepted as an IP address only when the entire trimmed value parses as an IP address. Therefore a version such as `v1.2.3.4` is not treated as an address. This conservative rule can omit indicators embedded in surrounding prose. Static strings are not associated with API arguments unless emulation recovers that call argument.
