# シンボリック実行

シンボリック実行は、指定した入力をビットベクトルとして表し、指定した命令アドレスに到達する値を探索します。実行用のリフタと既存の IR から SMT への式変換を使います。具体値だけのスカラー式には IR 評価器を使います。外部 SMT ソルバが必要です。PATH 上に `z3` または `bitwuzla` をインストールするか、`VELK_SOLVER` に `z3 -in` などのコマンドラインを設定してください。引数の引用符に対応していますが、シェルは起動しません。他の操作はソルバを起動しません。

関数一覧と逆アセンブル結果から仮想アドレスを選び、次のように実行します。

```sh
velk --explore check --find 0x401100 --avoid 0x401120 --stdin 8 app.elf
velk --explore check --find 0x401100 --stdin 8 --json app.elf
velk --api-docs symbolic
```

対象命令を実行する前に到達を判定します。同じアドレスが find と avoid の両方にあれば avoid を優先します。成功時には、標準入力、argv のバイト列、引数、メモリ、レジスタの具体値と、通過した命令アドレスを返します。上限付き探索の失敗は、到達不能の証明にはなりません。未対応の操作やアドレス列挙の打ち切りは診断に含まれます。テキスト出力では標準入力、argv、連続したメモリ入力をエスケープ文字列と16進数のバイト列で表示します。経路は長さと最初・最後のアドレスを表示し、`--json` では全アドレスとバイト配列を保持します。

JavaScript では `b.explore(start, options)` と `b.symbolic(start, options)` を使えます。オプションと状態 API の詳細は `velk --api-docs symbolic` を参照してください。

```js
const b = velk.open("app.elf");
const s = b.symbolic("check", {arguments: [0]});
const x = s.readRegister(7); // x86-64 System V の第1引数 rdi
s.constrain(x, "eq", s.constant(42));
s.evaluate(x); // ["0x2a"]
```

`Symbolic` はレジスタとメモリの項の読み書き、比較制約の追加、充足可能性判定、符号なし値の列挙、符号なし最小値・最大値の取得、`fork()` による複製、分岐または指定アドレスまでの実行に対応します。`step()` は分岐ごとに制約を持つ後続状態を返します。項はソルバのセッションに属し、複製した状態はそのセッションを共有します。使い終わった JavaScript の状態は `dispose()` で解放できます。Rust API は `velk::symbolic::{State, Term, Step, Options, explore}`、MCP ツールは `velk_explore` です。MCP には `path`、`start`、`options` を渡します。

実行ごとに独立した 4 KiB のスレッドローカル領域をマップします。`tlsBase` で
自動選択されるベースを上書きでき、重複やアドレスのオーバーフローは拒否します。
x86-64 の FS ベース、i386 の GS ベース、AArch64 の `tpidr_el0` をこの領域に設定します。
固定のスタックガードは `0x6a09e667bb67ae00`（i386 は下位 32 ビット）で、`canary`
で上書きできます。格納先は FS + `0x28`、GS + `0x14`、およびこのオフセットを使う
AArch64 sysreg ビルドの TP + `0x28` です。AArch64 glibc はグローバルガードを使い、
定義された `__stack_chk_guard` データシンボルも初期化します。x86 の自己ポインターを
除き、残りはゼロです。これはスタック保護の初期状態であり、TLS ローダーではありません。
明示したレジスター値とメモリー入力を優先します。`__stack_chk_fail` または
`__stack_chk_fail_local` の呼び出しで `stack check failed` として停止し、
シンボリック探索では診断にこの理由を含めます。

初期物理レジスタは、具体実行と同様にスタックポインタとスレッドポインタ以外をゼロにします。`arguments` はシンボリックにするスカラー引数の添字、`argumentValues` は具体値を指定します。`argv` は argv[0] を含む各文字列の長さです。文字列のバイトはゼロ以外、終端は具体値のゼロです。`memory` は書き込み可能なメモリ範囲を選びます。レジスタ入力には物理レジスタの添字を使います。64 ビットの精度を保つにはアドレスを文字列で渡してください。

上限は決定的です。`stepLimit` の既定値は経路ごとに IR 文 100000 個、`pathLimit` は状態 256 個、`addressLimit` はシンボリックアドレスの候補 8 個です。アドレスを符号なし昇順で列挙し、候補ごとに制約付き状態を作ります。候補が上限を超える場合は診断を返します。分岐先を先に深さ優先で探索します。具体入力は経路制約のもとで各入力の符号なし最小値を順に選ぶため、入力全体で整合します。実行時間による上限はありません。ソルバが応答しなければ呼び出しも待ち続ける場合があります。

対応対象はリトルエンディアンの i386、x86-64、AArch64 です。関数の先頭への末尾呼び出しにも対応します。i386 cdecl、System V x86-64、AAPCS64 の整数スタック引数、switch IR、上限付きの間接ジャンプにも対応します。

`b.solve("check", {arguments: [0], returns: {eq: 1}})` は最外側の戻り値を条件に探索します。条件は `eq`、`ne`、`lt`、`gt` です。大小比較は符号付き64ビット、等値比較は戻り値レジスタの全ビットを使います。32ビットの負の C 戻り値はレジスタ内でゼロ拡張される場合があります。CLI は `velk --solve check --returns eq:1 --stdin 8 app.elf`、追加オプションは `--symbolic-options '{"arguments":[0]}'` で指定します。Rust は `symbolic::solve`、MCP は `velk_solve` です。

`b.branchFeasibility("check", {arguments: [0]})`、Rust の `symbolic::branch_feasibility`、MCP の `velk_branch_feasibility`、CLI の `velk --opaque check --symbolic-options '{"arguments":[0]}' app.elf` で条件分岐を調べられます。全経路の探索が完了し、どの文脈でも実行可能でない側を `unsat` として報告します。上限、ソルバーの失敗、未対応処理で探索が不完全になった場合は、証拠のない側を理由付きの `unknown` とします。両側に実行可能な経路がある通常の分岐は省きます。一度も訪れなかった条件分岐は、探索完了時には両側が到達不能として報告され、不完全な探索では実行可能な証拠のない側が unknown になります。find、avoid、returns は指定できません。具体的な引数やメモリによる仮定に加え、Rust では State の制約を追加してから解析できます。

C++ ストリームは[エミュレーション](EMULATION.ja.md)と同じマングル名の判定と
文字列レイアウトを使います。単語・行入力はシンボリックなバイトを保ち、十進整数の
入力は上限を検査しながら計算します。出力は `inputs.stdout` に記録します。未対応の
インポート、入力失敗、整数のオーバーフロー、ストリームの書式変更は、診断を
出して該当する経路を停止します。

libc モデルはエミュレーターのインポート表と入力消費ヘルパーを共有します。静的リンクの関数にも、命令シグネチャ照合で呼び出し先が確認され、ライブラリ関数名が一意に確定した場合にモデルを適用します。曖昧な一致や未確認の一致ではリフトしたコードを実行します。モデルの適用に使ったアドレス、関数名、シグネチャ集合を診断に記録します。インポートのモデルでは、使用したインポートシンボルを示します。入力は `getchar`、`read`、`fgets`、`gets`、`getline`、`scanf`/`fscanf`/`sscanf` に対応します。scanf は `%d`、`%u`、`%x`、`%s`、`%c`、幅指定、代入抑制に対応します。scanf と getline のストリーム入力は stdin のみです。`read` は記述子0と `stdinDescriptors` に明示した記述子を同じ入力に結び付けます。文字列・メモリは `strlen`、`strnlen`、`strcmp`、`strncmp`、`memcmp`、`memcpy`、`memmove`、`memset`、`strcpy`、`strncpy`、`strchr` に対応します。整数変換は `atoi` と基数10/16の `strtol`、大小文字変換は ASCII です。`puts` と `printf` は出力を記録します。printf は具体値・シンボリック値の `%d`、`%u`、`%x`、`%s`、`%c` と `%%` に対応します。出力バイトは入力と同じ充足代入で `inputs.stdout` に格納します。文字列比較の非ゼロ値はバイト差です。libc が保証するのはその符号です。確保容量と puts の成功時戻り値はモデルの選択で、ホスト libc の詳細とは限りません。

AArch64 の可変長引数 I/O は ELF のみ対応し、Windows のデータモデルでは strtol を拒否します。モデルは命令数上限を消費します。メモリ処理は65536バイトまで、文字列探索は入力サイズに基づく4096〜65536バイトの有限範囲です。未対応インポート・書式、未対応のシンボリック引数の Apply、機械固有処理、フラグのみの分岐は診断で停止します。インポート先での停止指定はできません。呼び出し命令のアドレスを使ってください。コードは64 KiB、シンボリック入力は65536バイトまでです。Linux ELF の読み取り専用 `open`、記述子による `read`、`close` も
指定した仮想ファイルを使います。ゼロ除算の可能性がある演算は停止します。ループと再帰にも経路ごとの命令数上限が適用されます。

定数テーブルの読み取りでは、アドレスの符号なし値の範囲全体が256個以下のバイトアドレスに収まり、読み取り専用の一つのセクション内にある場合、経路を分割しません。1〜8バイトの読み取りでリトルエンディアンと符号拡張を保ちます。書き込み可能なメモリ、大きな範囲、セクション境界を越える読み取りでは従来の上限付きアドレス列挙を使います。SIMD の下位・上位インターリーブと拡張は8/16/32ビット、レーン合計、レーン加算、論理右シフトは8/16/32/64ビットでシンボリック値を処理します。切り詰めと符号付き・符号なし飽和パックは入力レーンが16/32/64ビット、先頭ゼロ数は値が8/16/32/64ビットの場合に対応します。他の未対応処理は診断で停止します。

`tests/data/crackmes/` の22個の C プログラムは、入力、比較、変換、テーブル参照、VM、状態遷移、チェックサム、内部呼び出しを扱います。リポジトリのルートからビルドして評価します。

```sh
bash tests/make_crackme_fixtures.sh target/crackmes
uv run --no-project tests/crackmes.py --cases table sum --variants elf > target/crackmes.jsonl
```

`--cases` と `--variants` を省略すると全プログラムと作成済みの全形式を評価します。ビルドスクリプトは両アーキテクチャの ELF を `-O0` と `-O2` で作成します。既存のシンボリック実行用フィクスチャと同じく、スタック保護と末尾呼び出し最適化を無効にし、外部呼び出し用のスタブを使います。Linux では対応するコンパイラがある場合、動的・静的リンクの libc 実行ファイルも作成します。評価では CLI の到達探索と戻り値探索を別々に記録し、所要秒数、診断、具体的な入力、ネイティブ実行の結果を出力します。評価側のタイムアウトの既定値は探索ごとに60秒で、シンボリック実行の決定的な上限とは別です。異なるアーキテクチャの実行には利用可能なら QEMU を使い、なければ同じ C プログラムをホスト上で実行したことを記録します。実行ファイルがない場合は `unverified`、入力が拒否された場合は `wrong` とします。終了コード0かつ出力が `success` と改行だけの場合に検証成功とします。入力スタブの実行をネイティブ検証には使いません。

ビルダーは両最適化レベルでスタック保護付きのバイト合計とテーブルの例、および i386 のバイト合計の例も生成します。AArch64 ではグローバルガードと TP + `0x28` を検証します。回帰テストは解いた入力をスタック保護付きのホスト実行ファイルで再生します。

Linux ELF の `read`、`write`、`exit`、`exit_group` システムコールは、シンボリックな標準入力と標準出力の記録を使います。未知のシステムコール番号では診断を出して停止します。i386 はライブラリー関数のモデルとシンボリックな argv に対応し、cdecl のスタック引数とポインターは4バイトです。argc は具体値で、argv のポインター配列はヌルで終端します。長さ0の文字列にも具体値のゼロ終端があります。

## シンボリックなファイル入力

`files` はエミュレーションと同じ仮想パスとバイト配列を受け取ります。各バイトを独立した
シンボリック入力にするため、配列が指定するのは長さであり値ではありません。初期バイトは
開き直しても共有されます。読み取りは位置の順に消費し、書き込みは対応する項を置換します。
ファイル入力も入力合計65536バイトの上限に含めます。モードと上限は
[読み込んだコードの実行](EMULATION.ja.md) と同じですが、1回のシンボリック転送は
65536バイトまでです。

`input` の5バイトを検査する関数の例です。

```sh
velk --solve solve_file --returns eq:1 app.elf --symbolic-options '{"files":{"input":[0,0,0,0,0]}}' --json
```

JavaScript では `b.solve("solve_file", {files: {input: [0,0,0,0,0]}, returns: {eq: 1}})`、
MCP では同じ `options` を `velk_solve` に渡します。`explore` と状態 API も `files` を
受け取ります。ファイルの項は既存のパス制約に入り、stdin、引数、メモリと整合する同じ
代入で値を決めます。`inputs.files` はパスごとの具体的な初期バイトです。このマップを
エミュレーションの `files` に渡して再実行できます。`inputs.fileOutputs` は同じ代入で
評価した反映済みの内容です。`fgets` はシンボリックな改行で分岐するため、行の境界も
解いたパスの制約に含まれます。

`rand` と `srand` は glibc の既定の乱数列を使い、初期シードは 1 です。
実行ごとに独立した乱数状態を持ちます。`time` は固定の Unix 時刻（既定値 0）を返し、
`time` オプションで変更できます。引数が null でなければ、対象のポインター幅で同じ値を格納します。
`signal` は Linux のシグナルハンドラーを記録し、直前のハンドラーを返します。
`alarm` は保留中のタイマーを置き換えて直前の秒数を返します。モデル内の時計は進まず、
シグナルは配送しません。`setbuf` は標準ストリームまたは仮想ファイルで null バッファーを受け付けます。呼び出し側が所有するバッファーには対応しません。
具体的なシードまたは一つの値に制約されたシードには具体的な乱数状態を使い、それ以外の記号的なシードには分岐時に複製するビットベクトル状態を使います。ソルバーの問い合わせの間に制約をリセットし、項の定義は保持するため、別の経路の制約が問い合わせを制限することはありません。
符号なしの値域の問い合わせでは、ゼロ拡張した値、真偽値、および上限が分かる数字の累積値の既知の幅を使います。値域が証明されていない算術には 64 ビットの探索を使います。

`exit` は仮想ファイルのストリームをフラッシュして実行を終了します。終了時ハンドラーの登録関数に名前があるか、インポートする場合は診断を出して停止します。libc の `_exit` 呼び出しには対応しません。
