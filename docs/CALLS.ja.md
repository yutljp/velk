# 関数のシグネチャ

`velk --summary BIN FUNCTION` は JSON オブジェクトを返します。
`signature` には次のフィールドがあります。

| フィールド | 意味 |
| --- | --- |
| `return` | 復元した C の戻り値の型。 |
| `params` | スタック上のものも含む名前付き引数の順序付き配列。各要素は `name` と `type` を持ちます。 |
| `parameterCount` | `params` に含まれる名前付き引数の個数。 |
| `callingConvention` | 解析が使う呼び出し規約。例は `SysV`、`Win64`、`Aapcs64`、`Aapcs32`、`Cdecl`。 |
| `variadic` | 復元した宣言が可変長引数を受け取るかどうか。 |

JavaScript の `f.signature()` もこれらのフィールドを返します。
JavaScript と MCP では次のスクリプトで概要を取得できます。
MCP では `velk_run_script` に渡します。

```js
const f = velk.open("tests/fixtures/metrics/calls.x86_64.O0.debug.elf").getFunction("sum_varargs");
({signature: f.signature(), summary: f.summary()});
```

概要の `calls` 配列は解析後に残った呼び出しを示します。
各要素は `block`（ブロックのアドレス）、`statement`（そのブロック内の番号）、
`target`（アドレスまたは null）、`indirect`、`callingConvention`、
`argumentCount`（個数または null）、`candidates`（呼び出し先候補のアドレス）、
`signature`（使える呼び出し先の宣言や復元したシグネチャを上記のフィールドで示したもの、または null）を持ちます。
文の番号は機械語の命令アドレスではありません。ポインター経由の呼び出しを解決できると、
呼び出し先が設定され、間接呼び出しではなくなります。
候補の配列が空でも呼び出し先が存在しないとは限りません。

x86 と ARM32 の内部関数の呼び出しでは、呼び出し先が変更する可能性のあるレジスターを引数の復元に
使います。呼び出し先が保持するレジスターには、呼び出し後に読む引数が残る場合が
あります。真偽値の定数代入によって合流する経路を区別し、後の条件がレジスターの
読み出しを制御する場合を扱います。解析の状態数が上限を超えると、保守的な引数の
推定を残します。
AArch64 と Go の引数の復元では、呼び出しが規約で変更できる全レジスターを
書き換えるものとして扱います。保存と復元の読み出しによって、余計な引数が加わる
場合があるためです。

ポインターの追跡では、保存した関数アドレスや定数データ内の値を、対象のポインター幅で
読みます。保存領域に重なる書き込みがあれば、保存した値の情報を破棄します。
不明なポインターや経路間の不一致によって、解決できない場合があります。

使える宣言がなければ、個数と型は推定値です。使わない引数を機械語から復元できるとは
限りません。可変長引数の宣言にはデバッグ情報や認識したレジスターの保存を使いますが、
任意の可変長引数関数への各呼び出しの引数まで決まるわけではありません。
不明な呼び出しの引数の個数は null のままです。規約名は解析のモデルを示し、
すべての関数がプラットフォームの標準規約に従うことを保証しません。
