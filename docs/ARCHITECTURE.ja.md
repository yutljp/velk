# アーキテクチャ

[English](ARCHITECTURE.md) | 日本語

velk がバイナリを C に変換する流れを段階ごとに説明し、各段階を担当するモジュールを示します。

```
バイナリ
  │  loader    ファイル形式の解析、セクションの配置、再配置の適用、関数と名前の検出
  ▼
Image          セクション、関数、シンボル、インポート、デバッグ情報
  │  lift      命令をデコードして IR の文に変換し、基本ブロックに分割
  ▼
FunctionIr     文と式からなる基本ブロック
  │  analysis  引数と戻り値、ジャンプテーブル、呼び出し規約
  │  passes    簡約、コピー伝播、不要コード削除、スタックフレームの復元
  │  ssa       SSA 形式、定数伝播、変数の分割
  │  typing    整数の幅と符号、構造体、デバッグ情報の型
  ▼
最適化済みの FunctionIr
  │  render    構造化 (if / ループ / switch)、命名、型付け、C の出力
  ▼
C · 逆アセンブル · IR · 関数の要約 (JSON)
```

## ローダー (`src/loader/`)

ELF（ELF32 を含む）、PE / COFF（PE32 を含む）、Mach-O を読み込み、`Image` を作ります。
`Image` にはセクション、名前とサイズ付きの関数、データシンボル、インポートが入ります。

- 再配置可能なオブジェクトファイル (`.o`、`.obj`) はリンカと同じように配置して再配置を適用し、呼び出しやデータ参照が実際の
  アドレスを指すようにします。
- 関数は複数の情報源から見つけます。シンボルテーブルとエクスポート、デバッグ情報 (DWARF、CodeView / PDB)、
  Go の関数テーブル、アンワインドテーブル (関数の正確なサイズも得られます)、最後に lift 中に見つかった呼び出しやコードの
  パターンです。
- 言語ごとのメタデータから、より良い名前を得ます。Rust と C++ のシンボルのデマングル、Go の型記述子、Objective-C のクラスと
  メソッドの一覧、Windows の例外処理 (SEH) テーブルです。
- デバッグ情報からは引数、ローカル変数、構造体フィールドの名前と型も得られ、後の段階で出力に使います。

## リフト (`src/lift/`)

x86-32、x86-64、AArch64、ARM32 のリフターが各命令をデコードし、IR の文に変換します。フラグ、レジスタの部分書き込み、ベクタ (SIMD) 命令、
アトミック命令を含め、対応している命令を正確に変換します。C で表せないマシン状態を読む命令 (`cpuid` や `rdtsc` など) は`__rdtsc()` のような
コンパイラ組み込み関数として出力されます。まだ変換できない命令は `unsupported` と出力されます。

x86-32 のリフターは ELF・PE、4 バイトのスタック、cdecl・stdcall・fastcall・thiscall の整数引数に対応し、引数数が不明な呼び出しは拒否します。

ARM32 のリフターは A32 と T32、条件付き実行、AAPCS のレジスタ引数とスタック引数を扱います。
関数アドレスの下位ビット、`bx` / `blx`、`$a` / `$t` / `$d` マッピングシンボルでコードのモードとデータを判別します。
ARM32 の浮動小数点・SIMD・システム命令と、型情報で指定されたワード幅を超える整数や集約型の引数・戻り値は未対応です。

命令の意味は実際の CPU と照合して確認しています (`src/lift/hardware/`)。同じ命令をプロセッサ上と IR インタプリタで多数の
入力に対して実行し、結果が一致することを確かめます。

ARM32 と x86-32 の整数命令の結果は Docker（`linux/arm/v7` / `linux/386`）での Linux 実行とも比較し、
各環境が利用できない場合は、スキップの理由を表示します。

## 中間表現 (`src/ir/`)

関数は基本ブロックのリストです。ブロックは文 (代入、ロード、ストア、呼び出し、分岐、リターン) を持ち、文は式 (レジスタ、定数、
算術演算、比較、ロード、型変換) から成ります。呼び出しには呼び出し規約と、わかる場合は呼び出し先で宣言された引数を記録します。

`src/ir/eval.rs` は IR のインタプリタです。テストではこれを使い、各変換が関数の動作を変えないこと、出力した C が同じ結果を
計算することを確かめます。

## 解析 (`src/analysis/`)

- **関数の要約**: 関数が引数として読むレジスタとスタック領域、戻り値、そして関数が戻るかどうか。要約はコールグラフ全体で
  計算するので、呼び出し側は正確な呼び出し先の情報を使えます。
- **ジャンプテーブル**: テーブル経由の間接ジャンプを `switch` 文にします。
- **間接呼び出し**: 復元した C++ vtable の情報で仮想呼び出しの呼び出し先を絞り込みます。
- **型付け**: 整数の幅と符号、ポインタ、復元した構造体、デバッグ情報の型。

C API 型ライブラリは、ターゲットごとに検証した宣言と構造体レイアウトを遅延読み込みし、
Mach-O には macOS SDK、PE/COFF には mingw-w64 と C ランタイム（DLL 名付きのインポートを使用）、ELF には glibc の
ヘッダーを使い、ターゲットごとに異なるレイアウトを保持します。

## 最適化パス (`src/passes/`、`src/ssa/`)

パスは計算内容を変えずに IR を簡単にします。

- 定数畳み込みと代数的な簡約、共通部分式の削除、コピー伝播、不要コードの削除
- コンパイラが定数との乗算に置き換えた除算と剰余の復元 (すべての入力で正確に一致する場合のみ)
- スタックフレームの準備処理の除去と、アドレスが外に漏れないスタック領域の通常変数化
- 定数伝播と、1 つのレジスタを別々の変数に分けるための SSA 構築

メモリアクセスの並べ替えや削除は、他のアクセスから違いが観測できないと解析で証明できた場合だけ行います。アトミック操作の
順序は保ちます。

## C の出力 (`src/render/`)

最適化済みの IR を C にします。

- **構造化**: 制御フローグラフを `if`、`while`、`do`/`while`、`for`、`switch` 文と、`break`、`continue`、途中の `return`
  にします。`goto` はグラフを構造化できない箇所でのみ使います。
- **変数**: 各値に名前と、使われ方に必要な C の型を付けます。名前はデバッグ情報があればそれを使い、なければ値の役割
  (ループカウンタなら `i`、戻り値なら `result`) か `vN` にします。
- **メモリ**: スタック上のオブジェクトは構造体、共用体、配列として宣言します。ポインタには要素の型を付け、アクセスを
  `p->field` や `p[i]` と出力します。配列の範囲は証明できた場合だけ仮定します。
- **呼び出し**: 呼び出し先のプロトタイプはデバッグ情報かよく使われるライブラリ関数の組み込みの表から得ます。可変長引数の関数には `va_start` /
  `va_arg` を使います。
- **出力**: コードに必要な補助定義と宣言はファイルの先頭に 1 度だけ出力するので、出力はそのままコンパイルできます。

## 外側の層

- `src/service.rs` はバイナリを開き、関数ごとの解析結果をキャッシュします。CLI、スクリプト API、MCP サーバーはすべて
  これを通ります。
- `src/main.rs` がコマンドライン、`src/script/` がスクリプト API に対して JavaScript を実行する部分、`src/mcp.rs` がその API を
  エージェントに公開する MCP サーバーです。
- `src/xrefs.rs` はクロスリファレンスとコールグラフを索引化し、文字列・定数の検索と関数の要約を提供します。
- `src/sigs/bytes.rs` はバイトシグネチャを照合して、シンボルを削除したライブラリ関数を識別します。
- `src/project/` はバイナリに結び付いた名前・型・コメントを JSON に保存し、解析と出力に適用します。

## 正しさの確認方法

[TESTING.ja.md](TESTING.ja.md) を参照してください。要点は、命令の意味を CPU と比較し、各パスを IR インタプリタで確認し、
出力した C をコンパイルして実行し IR と比べることです。すべてのテストバイナリのすべての関数がコンパイルできなければなりません。
