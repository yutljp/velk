# プログラムのバージョン比較

[English](COMPARISON.md) | 日本語

同じプログラムの二つのバイナリを比較します。

```sh
velk --compare first.elf second.elf
velk --compare first.elf second.elf --carry-annotations
velk --compare first.elf second.elf --project first.json --other-project second.json
```

結果は JSON です。`changed`、`identical`、`onlyFirst`、`onlySecond`、
`failures`、`transfer` の順に出力します。対応した各組には関数のアドレスと名前、
対応付けの `rule`、0 から 1 の `similarity`、`cDiff` と `blockDiff` が含まれます。
差分は一つの置換範囲として、削除行に `-`、追加行に `+` を付けます。
ブロック差分は最適化後の IR のアドレスと文です。空の差分は同じテキストを表します。
`identical` は同じアーキテクチャで機械語のバイト列と出力 C の両方が等しい場合です。
再配置や名前の違いだけでも `changed` に入ることがあります。比較結果は確認の補助であり、
動作が等しいことの証明ではありません。解析の失敗はバイナリ側と関数アドレス付きで報告し、
等しいと判断する根拠にはしません。

次の順番で対応を探します。

1. `name`: シンボル、デバッグ情報、別名、デマングル済みの名前が完全一致し、
   両側の未対応関数が一意である場合です。プロジェクトで付けた名前は根拠にしません。
2. `shape`: 同じアーキテクチャで既存の関数形状ハッシュ、数値定数、参照文字列、
   呼び出し先の数が一致し、候補が両側で一意である場合です。ハッシュは即値を区別しないため、
   ハッシュの一致だけでは対応を決めません。
3. `references`: 参照文字列、16 より大きい数値定数、既に対応した呼び出し元と呼び出し先を
   比較します。二つ以上の特徴が一致し、その中に文字列または二つの呼び出し関係が必要です。
   特徴集合の重なりが 0.55 以上で、両側の別候補との差が 0.15 以上である場合に対応します。
   新たに対応した関数を使って、さらに対応を探します。

`name` と `shape` の類似度 1 は対応付けの根拠についての値であり、本体の一致を意味しません。
`references` の値は共通する特徴数を特徴の和集合の大きさで割った値です。
曖昧な関数は未対応のまま残します。インライン化や削除された関数は最初のバイナリだけに、
追加された関数は二つ目だけに現れます。異なるアーキテクチャ間では名前だけで対応付けます。

`--carry-annotations` は最初のプロジェクトを読み、二つ目をアトミックに更新します。
関数名と関数先頭のコメントを対応する関数へコピーします。シグネチャ、引数とローカル変数の
注釈は、同じアーキテクチャで推定呼び出し規約、引数の格納場所と型が一致する場合に限ります。
ローカル変数の注釈には関数のバイト列の一致も必要です。
変数の対象は両側に存在する必要があります。
定義位置はブロックの位置で対応させます。命令コメントは同じアーキテクチャで関数のバイト列が一致する場合のみ、
バイト単位のオフセットで対応させます。コード・データ指定はスキップします。
宣言は宣言名でコピーします。コピー先に異なる型宣言がある場合、
型の意味が変わることを避けるため型のコピーを止めます。

グローバル変数は、形状と定数が等しい対応関数での読み取り、書き込み、アドレス参照位置から
対応付けます。関数、ブロック、文、参照種別の組の集合が両方向に一意に一致する必要があります。
これは推定なので、データ配置が変わった場合はグローバル変数の型を確認してください。
コピー先に既存の注釈がある対象は、名前だけの場合でも変更しません。
コピー先で既に使われている名前はスキップします。
`transfer.copied` と `transfer.skipped` にコピー元とコピー先の対象および理由を記録します。
繰り返し実行しても既存の注釈はコピーしません。同じバイナリやプロジェクトへのコピーは拒否します。

JavaScript API と MCP でも同じ比較とコピー処理を使います。

```js
const first = velk.open("first.elf", { project: "first.json" });
const second = velk.open("second.elf", { project: "second.json" });
const result = first.compare(second, { carryAnnotations: true });
result.changed.map(pair => ({ name: pair.first.name, rule: pair.rule, diff: pair.cDiff }));
```

MCP ではこのスクリプトを `velk_run_script` に渡します。比較は検出された全関数を解析するため、
適切な `timeout_ms` を指定し、結果を一部に絞って `max_output_chars` に収めてください。
解析中とプロジェクトの書き込み前に期限を確認します。ファイルの書き込みが既に始まっている場合、
スクリプトの制限時間を超えてもアトミックな更新を完了します。

`tests/comparison/fixtures` には二つの C バージョンから生成した x86-64 と AArch64 の
デバッグ情報付きおよび全シンボル削除済みのバイナリがあります。
`sh tests/comparison/fixtures/build.sh` は Clang、LLD、`llvm-strip` で再生成します。
`cargo test --release --test comparison -- --test-threads 3 --nocapture` は各対応をデバッグ名と
照合し、適合率と再現率を出力します。C とブロックの差分、曖昧な関数、インライン化、追加と削除、
Rust・CLI・JavaScript・MCP 経由の注釈コピーも確認します。

各比較には正解の関数ペアが十組あります。二つのデバッグ版では各 10/10 組、
二つのシンボル削除版では各 7/10 組を検出し、四つの比較で誤対応はありません。
合計の適合率は 34/34、再現率は 34/40 です。`renamed_before` と `renamed_after` は形状で、
編集された `route_before` と `route_after` は参照で対応します。シンボル削除版では
`edited` と区別できない二つの `ambiguous_*` 関数は未対応のままです。
